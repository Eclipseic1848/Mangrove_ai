# ADR-0039：只读外部世界与可复用数据的完整生命周期

- 状态：`accepted`，用户在本轮整改访谈中逐项确认并最终确认整体理解
- 日期：2026-09-04
- 决策来源：全工程审查后的产品整改访谈；尚未创建新 GitHub 工单
- 关联：ADR-0002、ADR-0004、ADR-0018、ADR-0035、ADR-0036、ADR-0037、ADR-0038
- 部分取代：ADR-0004 中未来受确认 Sink 的产品范围；精确网址授权不等于搜索任务授权的旧歧义；任务记录与业务数据无关联判断的删除方式

## 决策

Mangrove 首要服务不懂编程的业务人员。统一数据工作台继承文件、预览、自然语言、多轮修订、
报告、模板、个人记忆、自动任务与反馈；支持纯文件、纯联网及两者混合，不要求固定 Query
格式。需求不清时先在获准范围内检查数据并提出有依据的建议，再一次询问一个关键问题。

### 外部系统永久只读

Mangrove 可以按任务授权搜索、获取来源及调用所选模型，但不能修改外部数据库、同步业务系统、
发布、发送业务结果或操作社交互动。禁止项不是“确认后开放”或后期 Sink 路线。来源扫码登录
仅为恢复该 Owner 的读取权限，不授予发布、评论、点赞、收藏等能力。平台内部生成文件、保存
结果和任务内发布不属于外部系统写入；模型请求继续受已有任务外发授权约束。

用户明确提出搜索任务时，可以在确认的主题、时间、来源类别和有界获取范围内跨站搜索及读取，
无需事先逐一提供网址。仅输入精确网址仍不自动授权搜索、全站抓取或跨站跟链；需要登录或扩大
授权范围时另行请求 Owner 行动。发现链接不等于已经取得该链接内容。

### 原始数据保留与复用

保留本次实际取得的原件或内容快照、来源链接和获取时间；解析、清洗、摘要、翻译等结果与原件
分开，不因转换覆盖原始数据。提供人工阅读与程序处理的导出，Markdown、JSON/JSONL、CSV/XLSX
按内容和用途选择，不为每次任务强制生成全部格式。格式、解析缺口和关联身份必须可核对，不能
把摘要或截断预览冒充完整原始内容。

原始数据与结果可由同一 Owner 在平台内再次选择并处理，也可下载；默认保留直到用户主动删除，
空间不足时提醒和限制新写入，不静默清理或以重新采集替代历史内容。引用不扩大 Owner 权限，
来源中的密码、Cookie、Token 和二维码不属于可导出数据。

### 任务删除与共享引用

1. 删除任务时，未被其他保留任务引用的原始数据和结果一并处理。
2. 存在其他任务引用时，先展示受影响任务并由用户决定是否同时删除被引用数据；不能静默级联。
3. 用户明确确认删除共享数据后，其他关联任务及其独立生成的结果保留，标注来源已删除及受限
   能力；依赖该数据运行的任务先安全暂停，再完成删除。
4. 删除后的任务不得被描述为仍可完整重验或重跑；也不能暗中从缓存、重新抓取或备份恢复数据。
   保留不含业务正文的最小审计事实，不表示继续持有可下载正文。

具体软删除、物理清理及失败恢复由实现规格定义，但必须准确显示数据是否已删除；该产品决定不
授权现在删除本机真实数据、备份、Secret 或其他任务资产。

### 执行可见性与后期范围

优先复用成熟工具；缺少合适工具时，允许在隔离环境运行任务级临时脚本，不改原件、不获得任意
外网能力、不自动晋级为长期工具。执行事实、工具及脚本用途、判断摘要、异常与恢复进入默认
折叠的工作记录；沿用时间戳、实际耗时与 Provider 原生 Token/未知用量口径，不展示逐字思维链。

本次整改先覆盖表格、文档、PDF、图片和扫描件；音视频放后期。外部程序只读获取获准数据和
任务结果的接口也放后期；首阶段只提供平台内复用和结构化下载。后期接口不改变外部系统只读
边界，不自动增加外部程序创建或执行任务的能力。

## 取舍

拒绝只保留网址或摘要：不能满足后续人工/代码复用与来源核对。拒绝把所有原件转换为 Markdown
后删除原件：会丢失格式与非文本信息。拒绝删除任务时无条件保留全部数据，也拒绝无提示删除
其他任务正在使用的共享数据：前者违背用户清理意图，后者破坏关联任务。

以上是已确认的产品决策，不代表当前代码已实现；实施顺序、缺口和验收见整改计划及当前状态台账。
