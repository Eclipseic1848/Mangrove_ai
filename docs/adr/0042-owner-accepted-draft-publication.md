# ADR-0042：初稿先展示与用户接受交付

- 状态：accepted
- 日期：2026-09-14
- 决策来源：用户确认“初稿满意时手动停止后续验证并转为正式结果；没有操作则继续自动验证”。
- 继承 ADR-0019 的唯一 Publisher、文件 QA、幂等与提交点；增加用户接受这一显式业务放行依据。

## 决策

1. 宿主在完整输出文件集合可重开后冻结初稿，绑定 Owner、TaskRevision、Run、文件哈希。
   初稿可预览和下载，但不是正式 Delivery，不表示内容准确性已验证。
2. 默认自动验证不变。文档覆盖与通用候选检查均采用有界补救；连续两轮没有新增证据、
   已通过检查或缺口改善则停止重复补救，确认执行静默后等待用户决定，保留初稿和失败事实。
   更换文字、缓存命中和单纯更换解析器版本不算进展。不据此降低质量阈值或虚构证据。
3. 用户明确接受时冻结所看到的 draft_id，停止旧运行，并在新不可变修订记录 OwnerAcceptance。
   不再次请求模型，不修改旧修订和旧验证报告。新修订可沿用旧运行的配置语义供后续追问，
   但不伪造新运行或复用旧外发授权执行。
4. 发布仍经同一 Publisher：Owner、账号执行代数、冻结来源、当前修订、取消代数、删除、P0、
   文件 SHA/大小/格式集合/重开 QA 都不可豁免。接受与自动发布竞争时原运行提交点优先；
   取消在接受发布提交点前到达则不发布，提交点后按原有恢复规则收口。
5. 接受内容绑定文件集哈希和时间，写入新修订及正式 Manifest。验证状态保留 `inconclusive`，
   展示“用户接受”，不得展示“系统验证通过”。重复请求或发布中断只能恢复同一发布身份。
6. 不新增数据库 Schema、依赖、任务类型专用发布器或生产模型调用。初稿读取复用来源读使用
   与删除保护；主流程中的半成品文件解析失败只延迟初稿展示。

## 边界

用户接受是一种业务验收，不等于系统认证数据正确。它不授权对外发送、修改来源、运行新任务
或公开发布。当前接线覆盖 Pi 主执行的文档、表格与采集输出；Legacy/CoreMind Adapter 没有
初稿事件时不会伪造初稿。初稿文件需完整且不超过 128 MiB；文本内联预览最多 16000 字。
本决策不宣称已经完成 OCR 定位与读取置信度的分层改造，也不承诺真实模型耗时或提速比例。
