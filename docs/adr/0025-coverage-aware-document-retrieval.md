# ADR-0025：文档读取采用 Pi 自主检索与确定性覆盖完成门

- 状态：已采纳并完成工程实现；序数对象增量已工程验证，等待原真实任务最终复核
- 日期：2026-07-31
- 适用范围：Agentic Runtime vNext 的 PDF、图片型文档及后续可分页来源读取
- 决策来源：真实 109 页扫描 PDF 任务的性能与完备性复盘

## 背景

当前未提交试验实现会在 Pi 启动前逐页完成扫描 PDF 的高质量 OCR。它能避免 Pi 看不到
扫描内容，却把昂贵解析变成所有任务的固定前置步骤：用户只要求第一个单据时仍需等待整份
文件处理。相反，如果统一改成“从第一页读取，字段齐全即停止”，又会让“查找所有 XXX”
等需求漏掉散落在后续页面的记录。

Pi 无法判断未观察页面中是否存在目标。对于要求穷尽匹配的扫描文档，某种形式的全页发现
不可省略；可优化的是发现成本以及高质量解析的范围，不能以智能推理替代来源覆盖。

## 决策

### 1. Pi 理解覆盖语义，校验器冻结业务约束

Pi 必须结合用户当前要求、会话上下文、来源结构和历史澄清，自主形成
`CoverageContract`。契约表达获准范围、结果基数（首个、指定数量或全部）、完整性等级、
稳定顺序、对象边界、必需字段和停止语义，不包含 OCR Provider、页面批次或固定执行路线。

首个、指定范围、穷尽匹配和整源处理可以作为规范化表达，但不是互斥的 `TaskFamily`，更不
允许通过 `if "所有" in query` 一类关键词规则直接路由。确定性校验器只检查契约内部一致性、
权限和是否需要澄清，不能代替 Pi 理解用户目标。

对于“查找 XXX 的数据”等表达，Pi 应先结合上下文判断。高置信度时按理解继续，并向用户
展示“将返回首个/指定数量/全部匹配”的可见摘要；不同解释会实质改变结果或成本且置信度
不足时，只提出一个澄清问题。产品可以倾向完整作为安全默认，但不得把某个词写死成路线。

### 2. Pi 自主执行来源驱动的工具循环

Pi 负责观察来源、选择能力、安排调用顺序、决定是否先建立轻量索引、选择候选精读范围、
根据失败换能力或扩大读取，并在认为目标满足时提出停止。典型但非强制路线是：

```text
inspect → discover → read evidence → observe → expand/replan
```

当覆盖契约要求全部匹配时，Pi 可以自由决定页面优先级和批次，但最终必须让全部获准内容
单元参与可信发现；智能推理不能证明未观察页面中不存在目标。当契约只要求首个完整对象时，
Pi 可以在形成对象边界和必需字段证据后提议早停。

覆盖基数描述用户要求返回的顶层结果对象，而不是对象内部行数、人员数或字段数：`first`
表示首个对象，`ordinal + result_ordinal` 表示第 N 个对象，`count + result_count` 表示返回
N 个对象，`all` 才表示全部对象。序数目标必须证明目标之前的内容单元已被可信发现，并提供
覆盖到第 N 个对象的稳定顺序证明；目标之后的低质量页面不应阻断合法早停。

### 3. 文档检索 Module 暴露能力级 Interface

在来源读取 Seam 建立深文档检索 Module，向 Pi 暴露三个稳定能力，而不是一个包办规划的
`retrieve(...)`：

```text
inspect(source_snapshot) -> SourceMap
discover(source_snapshot, query, scope) -> DiscoveryResult
read(source_snapshot, unit_refs, needs) -> EvidenceReadSet
```

Pi 选择语义能力和 `needs`（文本、表格、版面等），Module 的 Implementation 隐藏页型识别、
OCR Provider、渲染分辨率、缓存路径、主备 Adapter 和证据坐标。已有 Phase 4A 的 MinerU
主解析、Paddle 表格增强与失败回退继续作为内部 Adapter。生产解析 Adapter 与测试内存
Adapter 构成真实 Seam；Interface 级测试不依赖内部 Provider 调用顺序。

`SourceDiscoveryIndex` 只能用于召回候选，不能直接支持正式结果。任何结果项仍必须绑定
`EvidenceReadSet` 中的权威证据。扩大用户授权的来源范围仍须确认。

### 4. 确定性覆盖账本记录事实，不替 Pi 规划

每次能力调用都更新 `CoverageLedger`，记录获准内容单元中哪些已观察、哪些已权威读取、
哪些质量不足、哪些仍未知以及解析版本。解析超时、空返回和低置信度不能记为“无匹配”。

覆盖账本不决定下一步工具；Pi 根据它重规划。确定性机制只强制以下不变量：权限和 Owner
隔离、外发边界、证据身份、失败状态以及已冻结覆盖契约不得被静默放宽。

### 5. Pi 提议停止，独立 Verifier 决定能否完成

Pi 不能自行签发完成结论。Verifier 必须重新检查覆盖契约、获准范围、覆盖账本、权威证据、
未覆盖原因和停止依据：全部匹配或整源要求存在未知单元时失败关闭；首个对象要求必须证明
稳定顺序、对象边界和必需字段，而不是只证明某页存在关键词。失败结果作为 Observation
返回 Pi 有界重规划，仍无法满足时才进入澄清或可操作失败。

## 后果

### 正面

- 局部任务不再被整份高质量 OCR 阻塞；
- 全量查询不会因为早停而静默漏页；
- 同一原件后续换问法可以复用轻量索引和已完成的证据读取；
- Pi 保留理解、规划、能力选择和动态重规划权，避免退化成新的固定流水线；
- OCR、缓存和主备解析的复杂度集中在一个深 Module，Pi 只学习稳定的语义能力 Interface。

### 代价

- 穷尽查询仍必须让全部扫描页参与某种可信发现，无法靠模型推理零成本跳过未读页面；
- 需要为索引质量、版本失效、候选漏召回和覆盖证明增加真实语料门禁；
- Pi 的契约理解和工具选择需要语义评测，确定性完成门需要独立回放，两类测试不能互相替代；
- 当前运行前生成整份 OCR sidecar 的试验实现不能直接作为最终 Interface，需要在实现阶段
  替换而不是继续叠加分支。

## 不变边界

- 不扩大来源授权、数据外发、权限或正式发布范围；
- 不以模型摘要、轻量索引或中间 sidecar 冒充权威证据；
- 不自动切换外部 OCR/模型；本地失败继续失败关闭；
- 本 ADR 不授权实现、默认入口切换、版本、标签或外部发布。
