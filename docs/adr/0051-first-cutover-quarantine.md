# ADR-0051：首次切换的固定历史隔离

- 状态：accepted
- 日期：2026-10-21
- 来源：#244；用户明确选择 B，批准一次有界只读与最小本地实现，生产变更另批。

## 背景

旧实例没有加载新排空门，部分历史读取和执行记录缺少原执行归属及完整终点。
新增审计结构不能补造这些事实。ADR-0049/0050 的真实停止证明和封存合同继续保留，
但不能作为所有遗留对象都能够补证的承诺。

## 决策

仅首次切换允许独立批准的维护例外：受控停止可能中断未观测在途，指定旧工作保持未知、
暂不可恢复，禁止重发。原 failure、事件、绑定及删除意图不改，不写虚假的 RunSeal。
Provider 已接收的请求及费用仍可能未知；旧本地执行者不得继续写生产库或外发后续操作。

复用 `app_settings` 的专用键 `deployment.first_cutover_quarantine` 保存固定清单。
显式迁移 `webui_0025` 初始化空权威；普通启动只验证，不自动建表或补值。
缺失、损坏、错配失败关闭。清单只允许从初始化空值一次登记，随后不可删除、替换或清空；
精确重放只返回原记录。它记录风险接受和身份，不证明旧任务已经自然结束。

清单精确绑定 Owner、资源类型、原 ID、可用代数、关联恢复身份与原件元数据摘要。
登记须由有效超级管理员留名，在原维护账号、真实停机、两库排他保留锁及提交前复核下执行。
不提供公网运维接口，不按整个 Owner 扩大禁用。可变 Grant 撤销和真实用量仍正常记录。

既有公共执行门复用该权威：执行绑定、Runtime、旧 Chat 冻结恢复、验证、学习、Grant/Relay、
来源读取、删除继续与后台认领均拒绝指定旧身份；数据库保护原记录和事件免遭迟到写与 REPLACE。
历史只开放无执行副作用且符合原权限的查看，deleting 来源仍不可读；新独立任务使用新身份。

部署前只对同一快照内原件匹配且隔离有效的精确行分类为历史例外。未知结构、遗漏、新异常、
当前可执行活动及未收口资源仍阻断。维护回执单列 `legacy_quarantine`，不把当前可执行域的
quiet 描述为历史全部自然完成。后续更新继续严格排空当前可执行域。

本次不写 RunSeal 的对象无需该链 root helper、mask 身份试验或600秒证明窗口。
实际部署 seal 的请求、PID、源码根、真实活动和新鲜回执校验保持。

## 验收与回退

必须实证旧身份无法经重启、恢复、新绑定、Grant、删除或后台重领绕过，新独立工作及角色权限
正常。只读材料不能被当作停止证明，本地回归不能替代服务器验收。

实际生产切换须有一个精确制品、目标、命令、备份恢复、时间预算和停止条件齐全的完整包批准。
无法补齐当前写入者或 Chat 冻结身份闭包时，在整包前置门退出，不进入生产修改。
不允许直接启动忽略该隔离权威的旧版回退，也不恢复旧数据库擦掉已登记隔离或新增业务事实。
