# ADR-0048：分阶段证据采集与宿主原样初稿

- 状态：accepted
- 日期：2026-09-24
- 决策来源：用户批准按中信权益任务复盘的通用任务方案修复和优化。
- 补充 ADR-0047 的首次模型启动情形；其余初稿接受、核对、Owner 与正式发布边界保持有效。

## 决策

1. 主题采集共用冻结范围、发现、低成本筛选、按需读取图片和评论、抽取、结果投影流程。来源适配负责访问与分页，领域规则负责字段和筛选；不为每家银行、酒店或商品新增执行分支。现有分析任务与文件任务继续复用各自入口，不建立第二套工作流引擎。
2. 计数单位明确冻结为笔记，不能用笔记数冒充独立活动或权益条目数。数量、候选、OCR、时间与完整性要求属于冻结策略。超出当前已实现粒度或边界的要求需澄清，不静默扩大。发现请求发出前占用候选额度，重复帖不退还检索额度。
3. 来源失败、正常无匹配、未完成、部分完成、达到目标分别表达。失败及严格要求未满足的快照仅作诊断，不能进入成功业务初稿。达到数量目标不代表穷尽平台，部分覆盖必须保留缺口。
4. 私有采集进度复用 ArtifactStore 的原子文件写入和现有 Owner、任务及模型连接身份；原件保存 SHA256。恢复需同一冻结范围、执行身份及处理版本，逐篇跳过已完成步骤；在途结果未知时留缺口，不自动重放。既有 Conductor 同 task_id 恢复使用原检查点，不重新规划。不同输入或身份须另建任务。
5. 业务明细只投影入选来源；候选审计保留全部。评论、图片和结构化明细带父来源状态与排除原因。逐字引用只表示可追溯，仍标记待核对；报名、领取、活动、使用等时间语义分开，不能拼接成单一区间。相同图片哈希记录共享来源关系，不据此合并业务活动。
6. 原样输出的完整格式集合有冻结来源哈希时，宿主确定性复制并复用现有文件重开、哈希与初稿冻结门，暂停等待用户决定。复制步骤不启动模型或容器，也不生成正式交付。
7. 上述原样初稿尚无 Pi 会话，用户明确选择继续核对时，可以在原 TaskRevision 与 Run 首次启动模型。资格保存在不挂载模型的宿主目录，绑定 Owner、任务、版本、Run 和初稿身份；启动前原子消费。已消费后丢失会话仍按 ADR-0047 拒绝恢复，不偷偷重做。未批准继续时保持等待。
8. 混合来源清单声明可用读取方式：JSON、表格等走本地文件工具，PDF／图片仅在原授权内走文档工具。能力描述不能扩大来源授权或用放宽权限掩盖类型错误。

## 边界

- 当前分阶段社媒来源接线为小红书；其他平台须接入并验证后才能宣称支持。
- 现有 Owner、连接版本、外发授权、初稿接受、QA 与唯一 Publisher 继续生效；无数据库迁移与新依赖。
- 处理版本变化应升级恢复指纹，不兼容的旧进度失败关闭。
- 持久进度不等于新增聊天“一键恢复”按钮。调用方必须保有同一 task_id 与冻结执行身份；新一轮聊天仍是新任务。
- 工程回归与历史快照离线重放不等于真实来源、真实模型或客户部署验收。
