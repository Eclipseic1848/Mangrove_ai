# ADR-0032：保留生产 Vault Key 时采用补偿控制验收

- 状态：`accepted`，用户于 2026-08-23 明确确认
- 日期：2026-08-23
- 关联：[ADR-0020](0020-provider-connection-broker-and-credential-isolation.md)、[ADR-0031](0031-durable-provider-qualification-batches.md)

## 决策

本轮不更换或轮换现有生产 Vault Key。G4 的 Vault 证据允许在原有完整轮换报告之外，二选一
使用保留密钥补偿控制报告。保留模式必须由启用且已审批的超级管理员明确接受剩余风险，并
同时证明：当前密钥能解开全部生产 Provider Secret、随机错误密钥不能解密、配置的备份目录
不含当前密钥材料、至少一份含 Provider Secret 的数据库备份可由当前密钥恢复且拒绝错误密钥、
一次性隔离环境中的完整轮换演练成功，以及检查前后生产密钥和数据库未被改写。报告不可覆盖，
必须绑定冻结 Manifest、数据库路径身份和干净 Git 提交。

既有 DeepSeek/百炼 Pi 报告可以复用，但只在其提交是当前提交祖先、Provider 关键目录未变化、
且资格脚本中的 Provider 执行函数语义摘要一致时成立。兼容检查失败、提交不可读取或证据身份
不一致时必须失败关闭并重新形成 Provider 资格，不得通过人工说明绕过。当前提交仍须重新生成
不访问 Provider 的传输安全报告。最终 G4 汇总必须在真实轮换报告和保留密钥报告中二选一。

由于当前没有目标 Linux/GPU 服务器，G5 的本机工程门以已完成的 Linux 容器、Compose、并发、
故障恢复和路径可移植性证据为准；真实目标服务器的 GPU/驱动/CUDA、生产容量、长期运行、
RAID/灾难恢复和可信 LAN PC 验收改为部署时服务器验收，不冒充当前已验证。未来获得服务器或
进入部署阶段时必须重新执行，不能复用本机结论。

`vnext_default` 仍是独立生产动作。即使 G4 最终报告通过，也不能自动扩大到所有用户。

## 取舍

保留现有密钥避免了用户明确拒绝的生产凭证变更和停服轮换风险，但无法证明历史上从未存在过
未登记的密钥副本，因此安全保证弱于真实轮换并销毁旧代际。限定备份目录扫描、恢复演练、
错误密钥拒绝、隔离轮换演练和显式风险接受共同降低这一剩余风险，但不消除它。部署时服务器
验收后移使当前没有服务器时可以完成工程收口，同时保留生产环境上线前必须取得的真实证据。
