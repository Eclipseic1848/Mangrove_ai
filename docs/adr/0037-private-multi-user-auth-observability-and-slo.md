# ADR-0037：私有多人部署的认证、可观测性与 P1 服务目标

- 状态：`accepted`，用户于 2026-08-30 明确确认
- 日期：2026-08-30
- 决策来源：GitHub Issue #86
- 关联：ADR-0020、ADR-0035、ADR-0036

## 背景

统一数据工作台将由多人通过浏览器远程使用。现有实现已有用户、管理员、超级管理员角色、
JWT 访问凭证、Owner 隔离、审计事件、健康检查和可选 OTLP，但还没有冻结远程部署的会话撤销、
限流、传输安全、日志边界、服务目标和外部 Provider 降级标准。

P1 不以公共互联网 SaaS 为目标。过早建设公开注册、跨组织租户、全球高可用或复杂计费会扩大
范围；继续使用不可撤销的长时浏览器凭证、含业务正文的日志或静默模型回退又不满足多人使用的
最低安全边界。

## 决策

### 1. 部署与角色范围

P1 面向一个组织管理的私有实例，支持约 10–50 名用户同时在线，通过 HTTPS 或 VPN 远程访问。
账号由管理员创建或审批，默认关闭互联网自助注册。角色继续使用 `user`、`admin` 和
`super_admin`，不新增“高级用户”或跨组织租户角色。

普通用户只能访问自己的任务、文件、对话、交付和来源登录状态。管理员默认只能查看跨 Owner
任务的编号、所有者、状态、耗时、Token 用量和错误类型；查看冻结业务正文必须填写原因并通过
现有 AuditView 留下不可变记录。任何角色都不能通过审计查看取得 Cookie、密码、二维码、密钥
或完整工具原始日志，也不提供用户冒充功能。

### 2. Mangrove 登录会话

每台设备拥有独立、可撤销的平台登录会话：

- 访问凭证最长 30 分钟；活动设备可使用轮换刷新凭证续期，但一次登录最长保持 7 天；
- 生产浏览器凭证使用 `Secure`、`HttpOnly` 和适当 `SameSite` Cookie，刷新秘密只保存服务端
  可核对摘要，不把长期凭证交给前端脚本；
- 当前设备退出只撤销当前设备；修改密码、停用账号或“退出所有设备”撤销该用户全部设备会话；
- 普通网页登录过期或退出不终止已在服务端运行的 Run，用户重新登录后继续查看和控制；
- 账号停用立即拒绝新动作，并在安全点暂停该 Owner 尚未终止的 Run；恢复账号不自动继续任务。

PlatformLoginSession 与 WorkSession、AuthenticatedSourceSession 及小红书 Cookie 分离。平台
登录续期不能延长来源 Cookie，来源重新扫码也不能恢复已撤销的 Mangrove 登录会话。

### 3. 最小限流

P1 使用一层共享、可跨进程核对的限流状态，避免仅靠单进程内存产生绕过：

- 同一账号或来源地址在 15 分钟内登录失败 5 次后，后续登录等待 15 分钟；成功登录清除失败计数；
- 已认证普通 API 每个 Owner 每分钟最多 120 次请求；创建、开始、继续和重试任务合计每分钟最多
  10 次；已建立的 SSE 流不按普通请求重复计数；
- 超限返回 `429` 和 `Retry-After`，不把账号是否存在暴露给调用方；连续超限形成不含业务正文的
  安全审计事实；
- 管理员不拥有绕过限流的隐式特权，内部健康检查使用独立端点和身份。

这些数值是 10–50 人私有实例的 P1 默认值。只有真实负载证据证明误伤或不足时才调整，不为尚未
存在的公共流量预建复杂套餐限额。

### 4. 传输与浏览器安全

除显式本地开发环回地址外，所有浏览器和 API 流量必须通过 HTTPS。部署边界由受信反向代理
终止 TLS，并校验代理来源；生产响应启用 HSTS、禁止 MIME 嗅探、限制 Referrer、禁止被任意
站点嵌入，并使用基于 nonce/hash 和明确来源白名单的 CSP。CORS 只允许配置的 Mangrove 前端
Origin，不能在携带凭证时使用通配符。

来源页面、二维码或工具结果只能作为受控数据呈现，不能扩大脚本、框架、表单或导航权限。

### 5. 关联 ID、日志与指标

每个入口请求生成或校验受限长度的 `request_id`，并沿执行链关联 `task_id`、`revision_id`、
`run_id`、`work_session_id` 和 Trace Context。外部输入的关联 ID 不能直接覆盖内部权威身份。

运行日志保留 30 天，只记录时间、关联身份、业务阶段、工具或 Provider 类别、耗时、Token 已知
值/未知数和错误类型。安全审计保留 180 天，只记录操作者、动作、对象、理由、结果和时间。
两类记录都不得保存对话正文、文件正文、Cookie、二维码、密码、密钥、完整 Prompt/响应或工具
原始返回内容。

最小指标包括 HTTP 可用性与延迟、任务各状态数量、队列深度、SSE 建连/重连、Provider 延迟与
确定/未知失败、已知/未知 Token、来源重新认证状态、登录失败/限流和数据库就绪状态。指标标签
只能使用低基数状态和类别，不能把 Owner、Task、URL 或正文作为标签。

### 6. P1 服务目标与告警

P1 采用工程服务目标，不对外宣称公共生产 SLA：

- Mangrove 自有 UI/API 按自然月目标可用性 99.5%，提前通知的计划维护窗口不计入；
- 打开工作区及暂停、继续等普通控制操作，95% 在 2 秒内返回已接受或确定错误；
- 提交任务后 2 秒内持久化并展示首个“已接收/正在处理”结构化进度；
- 核心服务连续 5 分钟不健康时告警管理员；月度可用性、2 秒目标或错误预算持续越界时形成
  可追踪告警，而不是只写本机日志。

小红书、模型服务等外部依赖的等待时间不计为 Mangrove 自身不可用，但界面必须明确显示正在
等待哪个外部类别、最近状态和可执行动作。自身没有持久化任务或无法展示状态时仍算 Mangrove
失败，不能把所有错误归因给 Provider。

### 7. Provider 降级

Run 始终使用用户冻结的模型和 RuntimeBinding。外部 Provider 变慢、限流或故障时允许在已有
安全规则内对同一冻结模型做有界重试；结果未知则暂停并请求用户决定是否承担重复调用风险。
不允许静默切换模型、Provider 或低质量执行链，也不把等待伪装为持续思考。

## 拒绝的替代方案

- **直接面向公共互联网开放注册**：P1 没有公共 SaaS 的业务目标和防滥用证据，拒绝。
- **只使用长时 JWT 且不保存会话状态**：无法可靠撤销丢失设备或停用账号，拒绝。
- **把对话和工具原文写入日志方便排障**：扩大敏感数据面，拒绝；正文只走受审计查看。
- **Provider 失败后自动换模型**：违背用户模型选择和冻结运行语义，拒绝。
- **把外部平台故障都算 Mangrove 正常**：若平台不能持久化并解释等待状态，仍是自身故障，拒绝。

## 后果与完成门

P1 实现必须在现有认证、Owner 隔离、AuditView、结构化进度和 OTLP 接缝上做最小增量，并以自动
测试证明会话撤销、账号停用暂停、限流、HTTPS/CORS/CSP、日志脱敏、关联 ID、指标和 Provider
降级。真实远程候选还要用 10–50 人目标下的负载与故障演练验证 99.5%/2 秒/5 分钟标准。

本 ADR 不证明当前实现已达标，也不授权公网开放、生产部署、读取生产数据、配置真实 Secret、
发送外部通知或发布 Release。上述动作仍遵守独立人工门。
