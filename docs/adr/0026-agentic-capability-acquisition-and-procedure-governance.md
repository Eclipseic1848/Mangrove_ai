# ADR-0026：Pi 自主能力获取采用隔离获取、不可变能力包与双作用域自动化方案

- 状态：`accepted`；第 6 项成熟度定义由 [ADR-0029](0029-capability-validation-lifecycle-and-platform-publication.md)
  修正；AC-04/AC-05 已验证，AC-06 按 ADR-0028 完成 Sidecar 工程验证并通过用户灰度验收
- 日期：2026-08-02
- 决策来源：[Agentic 能力获取、SOP 与对话上下文规格](../plans/2026-08-02-agentic-capability-sop-context-spec.md)
- 上游：[ADR-0017](0017-agentic-runtime-vnext.md)、[ADR-0019](0019-vnext-delivery-and-default-cutover-state-machine.md)

## 背景

Pi 已能在任务级 Docker 中使用文件、Shell、代码和既有领域工具，但当前
`PiRuntime.start/resume` 只进入挂载用户来源的业务执行网络。`EgressPolicy` 虽已定义
`dependency_acquisition`，尚无“不挂载用户来源 → 获取并冻结能力 → 退出联网环境 →
挂载来源执行”的正式编排。现有 `CapabilityRegistry` 只登记内置固定实现；
`skills/*.md` 与 `data/templates/*.md` 又是平台全局文件，没有个人所有权、不可变版本或
发布审核，不能直接承担用户确认的个人/平台 SOP。

允许 Pi 在业务环境直接联网安装虽然简单，但会同时暴露用户来源和公网，并污染项目或宿主
依赖。反过来，为每个工具单独启动容器会把版本隔离误做成进程隔离，增加无必要的启动和
编排成本。

## 决策

1. 能力获取和业务执行是互斥阶段。获取阶段不挂载用户来源、不注入 Provider Secret；
   业务阶段只装载已冻结能力包，并继续按任务授权限制网络。中途缺能力必须退出业务环境，
   不能原地开放公共依赖站点。
2. Pi 可以在有界预算内从官方仓库、npm、PyPI、GitHub Release 和已登记 MCP/Skill 来源
   自动获取能力；陌生 URL、来源不明可执行内容、新外发目标或更高权限必须暂停确认。
3. 获取结果形成不可变 `CapabilityPack`。每个版本固定来源、依赖、哈希、能力声明、权限、
   运行入口和验证证据；保存到 Mangrove 管理的能力仓库或可移植制品中，不安装到 Windows
   全局环境或 Mangrove 主 Python/Node 环境。
4. 存储隔离不等于每能力一容器。一个任务环境可以同时只读装载多个已获准能力包；本地 MCP
   在任务期间复用，管理员审核的高频平台 MCP 才可在后续生产门中评估常驻 Adapter。
5. `AutomationProcedure` 组合一个或多个能力包，保存适用条件、优先路线、权限要求、完成门
   和失败处理。它不冻结任务执行顺序，Pi 仍在 `GoalContract` 内根据 Observation 重规划。
6. 方案成熟度与作用域正交。本文当时采用的 `draft | verified | deprecated` 状态已由
   [ADR-0029](0029-capability-validation-lifecycle-and-platform-publication.md) 修正为成熟度、生命周期
   与运行资格三轴；`personal | platform` 作用域保持不变。首次成功只产生个人草稿；合成测试、
   至少一次真实任务和失败关闭测试通过后才可验证；平台方案必须由管理员或超级管理员从已验证
   个人快照审核发布。
7. 个人方案只对 Owner 可见。发布平台版本采用独立脱敏快照，不把原记录改成全局可见；
   个人后续修改不能影响平台版本。个人和平台版本都不可原地覆盖，升级生成并行候选。
8. 原文件、真实结果和证据留在 Owner 隔离的任务记录中。个人方案可以引用本人的任务 ID，
   但不得复制业务原文、凭证明文或宿主路径；平台方案默认只携带合成或脱敏夹具，真实样本
   进入平台发布必须另获授权。
9. Pi 按适用程度、验证状态、版本、权限和历史成功率选择个人或平台方案，记录选择原因并
   允许用户切换。失败学习只能生成新的个人候选版本，不能修改正在使用的验证版本或平台
   版本。
10. 时间、下载量、磁盘、重试和并发预算由管理员配置。达到预算后返回已尝试内容和缺口，
    不得无限搜索、下载或静默扩大权限。
11. 现有固定 Capability、手写 Skill 和分析模板保留为 Legacy 资产，只能经显式 Adapter
    导入新目录；不得原地迁移、批量公开或把旧使用次数冒充新验证证据。

## 考虑过的替代方案

- **直接安装到宿主机或项目环境**：首次调用简单，但会形成依赖漂移、跨任务污染和不可复现
  环境，拒绝。
- **每个工具单独启动容器**：隔离最强，但工具组合、冷启动和资源成本过高，拒绝作为默认；
  只对独立 MCP 或高风险执行器保留 Adapter 选择。
- **所有 SOP 都是平台全局模板**：无法隔离个人经验、任务引用和连接，拒绝。
- **一次成功即自动共享**：无法证明泛化和失败关闭，且可能泄露业务数据，拒绝。
- **用关键词把 SOP 变成固定路由**：会重建被 vNext 废弃的 `TaskFamily` 问题，拒绝。

## 后果

- 需要新增能力获取、能力目录、方案学习/发布和能力装载等深 Module，但业务调用者只依赖
  少量 Interface；工具、MCP 和 Skill 的安装差异留在内部 Adapter。
- 首次获取会产生下载和验证成本；相同版本后续通过共享缓存和只读装载复用，不重复安装。
- 新能力不能绕过 Verifier、正式 Publisher、Owner 隔离或任务外发确认。
- Windows Docker Desktop 下的原生能力装载按
  [ADR-0028](0028-task-level-capability-host-sidecar.md) 使用任务级单 Sidecar；默认关闭，
  不改变无原生能力任务路径。
- 本 ADR 不授权实现、安装新工具、创建远端仓库、提交、推送、版本、标签或平台发布。
