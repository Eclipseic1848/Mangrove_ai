# ADR-0044：用户授权的结果邮件与 Slack 通知

- 状态：accepted
- 日期：2026-09-16
- 决策来源：用户要求恢复 SMTP/Slack 配置，以及自然语言指定收件人后发送结果的能力。
- 部分取代：ADR-0039 的“不得发送业务结果”，仅限下述邮件和 Slack 通知例外。

## 决策

1. SMTP 与 Slack 统一在“平台配置 → 通知”维护，管理角色可修改、启停和检查；密钥继续使用
   SecretRef。SMTP 检查仅连接登录；Slack Bot 检查仅验证身份，不发送测试消息，不冒充频道权限验证。
2. 用户可在正式结果中主动选择正文、附件、收件人后发送；也可在当前自然语言输入中明确要求
   把结果发给指定邮箱或已配置 Slack 频道。不要求固定句式，明确授权不重复弹确认框；缺失或
   模糊的信息要求补充，不猜收件人、不改投其他频道、不忽略文件格式限定。
3. 识别只读取当前用户原文；附件、网页、助手输出和历史批准标记均不产生发送授权。宿主核对
   原文证据与目标，所选文件限当前 Owner 当前版本的正式输出。报告发布和发送回执分开。
4. SMTP 发送真实 MIME 附件。Slack 正文可用 Webhook；文件使用 Bot Token、频道 ID 与官方文件
   上传接口。一次发送冻结目标，配置或账号变化在网络写入前复查；单次附件上限 20 MB。
5. 复用持久执行领取和跨进程锁拦截重复请求；发送结果未知时不自动重发，不以请求中断证明
   未发送。接受初稿形成正式结果后同样适用；发送异常不撤销或伪装报告发布结果。
6. 自动通知不扫描旧历史任务补发。未完成任务不能自动发送草稿；未提供文本报告时不拿摘要
   冒充正文，提示使用附件。SMTP/Slack 接受请求不代表收件人已阅读。

## 不变边界

不开放外部数据库写入、业务系统同步、社交发布/互动或任意网络写工具；旧确认发送路由仍拒绝。
隐藏旧采集兼容配置只改变入口，保留后台值与兼容读取。工程验证使用合成凭据和模拟服务，
不代表真实邮件投递、Slack 权限或自然语言模型识别的生产验收。
