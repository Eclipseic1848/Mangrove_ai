# ADR-0029：能力验证、生命周期与平台发布采用三轴治理

- 状态：`accepted`
- 日期：2026-08-06
- 决策来源：AC-07 `grill-with-docs` 用户逐项确认
- 上游：[ADR-0026](0026-agentic-capability-acquisition-and-procedure-governance.md)、
  [ADR-0028](0028-task-level-capability-host-sidecar.md)

## 背景

AC-06 已完成 Python 表格 Tool 与 Everything MCP 的管理员工作台灰度验收。AC-07 需要避免
一次任务成功直接污染平台目录，同时为版本升级、安全漏洞、管理员审核和普通用户开放提供
不同的控制语义。ADR-0026 把 `deprecated` 放在成熟度中，无法区分“证据是否充分”“是否仍受
推荐”和“当前是否安全可执行”，也没有冻结平台签名、漏洞例外和管理员审计查看的边界。

## 决策

1. AC-07 建立同时适用于 CapabilityPack 和 AutomationProcedure 的治理契约，但本阶段只让
   CapabilityPack 实际验证和发布；Procedure 的蒸馏、组合、选择和实际晋级留在 AC-08。
2. 验证严格绑定不可变 digest。Owner 主动发起验证；合成 Smoke、已授权 Owner 真实任务重放、
   失败关闭与权限测试、安全扫描、来源/锁文件一致性和 SBOM 全部通过后，系统才确定性地把个人
   版本标为 verified。新 digest 不继承旧证据，但授权和冻结来源仍有效时可以重放既有任务。
3. 能力治理拆为三个正交轴：成熟度 `draft | verified`，生命周期
   `active | deprecated | revoked`，运行资格 `eligible | quarantined`。弃用只停止新任务推荐，
   历史冻结任务仍可执行；撤销禁止新任务、重试和恢复；系统可以因安全门自动隔离，但最终撤销
   或恢复必须由管理员决定。
4. Trivy 直接扫描最终目录或镜像，Secret、Critical、签名失效、越权和隔离突破绝对阻断。
   已有修复版本的 High 必须升级；无修复且经验证风险路径不可达的 High 只允许管理员在
   admin_gray 范围限期接受，默认 30 天、最长 90 天，到期自动隔离。Medium、Low 和 Unknown
   留证但不自动阻断。漏洞库有效期为 7 天；过期不停止既有灰度运行，但禁止新晋级、发布和解除
   隔离。
5. 进入 verified 或平台候选时用 Syft 生成 SBOM。平台发布使用项目目录和数据库之外的 Cosign
   本地加密私钥绑定确切 digest，装载前验证签名；外部 keyless、KMS、Fulcio 和 Rekor 后置。
6. 平台发布从已验证个人版本生成独立脱敏快照、新 digest 和独立生命周期，不修改个人 scope。
   受限审计保留来源关系；个人版本后续修改、弃用或删除不影响平台快照。发布默认进入
   admin_gray，面向普通用户开放是另一个显式动作，不自动推荐或改变历史 TaskRevision。
7. 管理员和超级管理员沿用同一治理类型，一名管理员可以显式发布、弃用、回滚、撤销或接受
   High 风险；每次动作必须保存 actor、时间、原因和适用范围，不允许任务成功或 Agent 自主
   触发。双人审批留到团队部署阶段。
8. 管理员默认可查看跨 Owner 的任务管理信息。读取个人 Prompt、原件、候选或交付正文必须
   进入审计查看，填写原因并记录读取对象；普通列表不得提供无痕正文访问或批量导出。
9. Python 表格 Tool 与 Everything MCP 作为 AC-07 两条真实纵切面，其他已由 AC-06 验证的
   Node、CLI 和 Skill 只做统一治理契约回归。管理员设置内提供最小能力治理页面，不新增一级
   导航；完整自动化方案中心仍属于 AC-09。
10. 数据库变化只允许纯新增、幂等迁移，执行前备份；既有灰度包、历史验证和冻结选择不改写，
    也不因 AC-06 验收通过自动晋级。迁移、真实工具下载、平台发布、普通用户开放和外部发布均
    保持独立人工控制。

## 考虑过的替代方案

- **继续使用 `draft | verified | deprecated` 单轴状态**：无法表达已验证但被替代、紧急安全撤销
  和临时自动隔离的差异，拒绝。
- **一次成功后自动晋级或发布**：缺少失败关闭与真实泛化证据，也绕过管理员控制，拒绝。
- **发布时直接修改个人 scope**：会耦合个人与平台生命周期并泄露个人元数据，拒绝。
- **发现任意 CVE 就阻断**：误阻成熟工具且缺少风险层次；改用绝对禁项、严重度、修复状态和
  限期例外的组合门。
- **首版使用 Cosign keyless 或企业 KMS**：引入外部身份、网络和密钥基础设施，对本地学习环境
  过重，后置。
- **发布即向所有普通用户开放**：把信任跃迁和权限扩大合并为一步，拒绝。

## 后果

- AC-07 必须新增验证证据、三轴状态、隔离、风险接受、平台快照、签名和审计 Seam；调用方不能
  再把一次成功、获取 READY 或 `deprecated` 当成完整信任结论。
- 新 digest 的验证成本高于直接继承，但可以复用仍获授权的冻结真实任务重放，避免要求用户重复
  上传。
- 平台能力即使通过发布，也只默认进入管理员灰度；普通用户权限和默认选择不受本 ADR 自动改变。
- 本 ADR 记录领域和架构决策，不授权代码实现、数据库迁移、依赖下载、GitHub 写入、提交、推送、
  平台发布或普通用户开放。
