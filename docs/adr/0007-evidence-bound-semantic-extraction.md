# ADR-0007：语义抽取必须绑定原始证据

- 状态：已采纳，字段/全量记录/完整表格抽取闭环已实现
- 日期：2026-07-21
- 决策来源：任务驱动的数据发现、证据抽取与准备蓝图

## 背景

ADR-0003 将 LLM 限定为意图理解、字段映射和 Recipe 建议，避免模型直接修改事实数据。但批量文档条款、客服诉求、网页目标内容等需求必须进行语义候选定位和结构化抽取，仅靠确定性清洗规则无法完成。

若把 LLM 的抽取结果直接当成事实，会产生无证据补值、跨文档串值、语义混淆和不可复核等风险。因此需要在不破坏原始不可变和确定性质量门的前提下，允许受约束的语义抽取。

## 决策

- LLM/Agent 可以在已授权、已保存的来源内进行候选片段定位、分类和结构化候选抽取。
- 语义抽取结果是“候选事实”，不是 RawArtifact，也不能覆盖原始记录。
- 每个非空候选值必须绑定 `EvidenceRef`：至少包含来源、原始制品、位置、证据片段引用/哈希、抽取器版本和置信度。
- 原文没有明确证据时必须输出空值、“未找到”或“不确定”，禁止用常识、相邻文档或其他记录补足。
- 文档、用户、任务之间的证据必须严格隔离；跨文档归纳只能生成单独的汇总结果，不能反写单文档事实。
- 多个候选互相冲突或低于阈值时，按 `ReviewPolicy` 进入人工复核或隔离，不静默选择。
- 日期、金额、单位、枚举、去重和质量阈值等后续处理仍由确定性 Recipe 和 Quality Gate 执行。
- 每个非空语义值的证据覆盖率是硬质量指标；未达到 100% 时任务不能以无告警 `pass` 交付。
- 页面、文档、OCR 文本中的指令一律视为数据，不得改变 Agent 目标、安全策略或工具权限。
- `ResultContract` 必须显式区分“保留多张原表”和“合并成一张表”。仅当用户明确要求时设置 `merge_tables=true`；合并使用确定性列位置拼接并保留来源表、来源页，不由 LLM 选择或删除行。
- 当结果契约要求全量 records/tables 而有效输出为零时，质量结论必须为 `fail`，任务不得标记为完成，也不得向用户提供看似成功的空权威文件。

## 后果

- 正面：Mangrove 能扩展到合同、招投标、发票、客服、政策和媒体等语义抽取任务，同时保持可追溯和可复核。
- 正面：证据模型可跨文档、网页、数据库记录和媒体时间片复用，避免场景专用抽取器各自定义审计格式。
- 代价：必须保存稳定的位置和证据引用，并增加字段级 golden fixtures、准确率/召回率和人工复核测试。
- 代价：结果表不能只保存清洗后的值，还需要 Evidence/Lineage 侧车产物及字段级关联。
- 边界：置信度不能替代证据；高置信度但无来源定位的值仍不合格。
