# ADR-0010：文档任务以独立文件或文件集为稳定边界

- 状态：已采纳并落地
- 日期：2026-07-23

## 背景

旧工作区把所有已上传文件维护在一个可勾选列表中，再通过“某文件参与过的最新任务”恢复右侧结果。新文件会被误带入旧范围；同一文件参加多个任务后，点击不同文件可能命中同一个累积任务，导致历史结果串线。

## 决策

引入稳定的 `document_task_units`：

1. `single_file` 只包含一个上传文件；一次 Agent 执行只处理该文件。
2. `file_set` 由用户显式选择、命名，可包含多个已有文件；一次 Agent 批处理并产生一个合并结果。
3. 对话、抽取方案、复核、结果和不可变版本历史全部归属 `unit_id`。
4. 勾选只表示“准备组合文件集”，不改变当前任务执行范围。
5. 文件集成员点击只改变原文预览；右侧始终展示文件集级对话和合并结果。
6. 同一上传文件可以加入多个文件集，原始制品不复制。
7. 历史累积任务按父版本关系和首次新引入文件无损迁移；保留原任务、原上传范围和产物。
8. 已进入文件集的 `single_file` 默认从主列表折叠，避免同一文件重复展示；用户仍可展开“已归组的独立任务”查看其原有独立结果。
9. 顶层任务单元的删除采用软归档：只从工作区隐藏，刷新不恢复，但原文件、执行版本和结果继续保留。

## 实现约束

- 新任务使用 `/api/data-tasks/document-units/{unit_id}/runs` 查询历史；`document-runs/by-upload` 仅保留兼容用途，不得作为前端任务归属依据。
- 前端请求缓存键必须包含 `unit_id`，切换任务时取消或丢弃过期结果。
- 文件集成员调整必须由用户确认后创建下一版本，不得静默重跑或覆盖旧结果。
- `DELETE /document-units/{unit_id}` 只设置 `archived_at`，不得级联删除上传制品或历史任务。

## 结果

独立文件和文件集拥有可解释、可持久化的任务边界；快速切换和一份文件参加多个集合时不会串历史。代价是新增任务单元表、成员关系表、迁移逻辑和显式文件集创建交互。
