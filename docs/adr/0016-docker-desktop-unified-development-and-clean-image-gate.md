# ADR-0016：Docker Desktop 统一开发环境与干净镜像验收门

## 背景

仓库现有 Dockerfile 和 Compose 仍启动旧 Streamlit/WebSocket 程序，而当前 Mangrove
已经采用 React、FastAPI 和 Phase 4B 工作台。继续让前后端运行在 Windows、只把部分
依赖放进 Docker，会使日常运行、依赖事实和未来服务器部署长期分叉；但只验证源码挂载
的热更新容器，也无法证明干净镜像可以独立部署。

## 决策

Windows 开发环境统一由 Docker Desktop 管理。`start_all.bat` 和 `stop_all.bat` 一次
定向启停当前完整开发环境；开发容器挂载源码并支持前后端热更新。8B-1 另由一键验收脚本
自动构建不挂载宿主源码的干净镜像，在隔离项目、数据和端口上验证 Phase 4B 闭环。

日常容器通过受控挂载复用现有任务资料和配置，但首次切换前必须检查并备份；测试栈不得
读取或修改日常数据。停止服务不删除持久卷，任何重置或清理都必须使用独立、需确认的入口。

## 后果

- 日常开发仍保留热更新，但不再依赖 Windows 宿主机直接运行前后端；
- 干净镜像门防止把源码挂载环境冒充可部署结果；
- 最终服务器仍需在整个工程完成后的 8B-2 做 Linux、GPU、存储、并发和恢复实机验收；
- 旧 Streamlit/WebSocket Docker 配置作为历史入口保留，不直接覆盖。
