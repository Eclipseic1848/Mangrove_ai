# ADR-0049：历史未知 Run 的停止裁决与不可变封存

状态：accepted

日期：2026-10-20

关联：[#244](https://github.com/Eclipseic1848/Mangrove_ai/issues/244)

## 背景

历史模型结果未知可以与本机执行已经停止并存。把所有未知永久当作当前在制会阻断安全更新，
而取消旧 Run、清除 failure 或批量标闲又会毁坏原事实。用户已确认：逐 Run 补齐停止证明、
封存禁重发并留下审计后，可以解除该历史项的部署阻断，生产执行仍需具体方案单独批准。

## 决策

1. 不新增成功或结果已知状态，不改写原 Run、failure、事件、候选与结果。原结果仍未知。
2. 通过显式 `webui_0024` 迁移新增一张不可变封存表，同时承担禁止重发权威与裁决审计。
   身份唯一到 Owner/task/revision，记录原 run、绑定及状态摘要、账号代数、停止证明、
   操作者、审批引用和幂等请求；不与业务表级联删除。
3. 仅本机已批准的停机维护窗口允许写入。逐 Run 原始观察与当前停机事实分开核验；JSON
   结构、摘要、idle 或空锁不能独自证明停止。证据缺失或冲突继续阻断，不补造旧绑定。
4. Kernel、持久写入、模型及文档 Grant、候选复验和业务动作均读取同一权威。已封存原
   Run 不可继续或重发；新修订仍遵守既有显式任务合同，不取消旧 Run 来清除未知。
5. 部署检查仅豁免精确匹配且证据有效的该条历史未知；其他持久和资源阻断保持独立。

## 后果与回退

本决策对 [ADR-0015](0015-workspace-audit-tombstone.md) 的正常清理流程增加明确限制：涉及
已封存未知 Run 时先拒绝删除，不进入文件清理再尝试保留精简墓碑，防止销毁本次要求保全的
原始未知事实。后续保留期限或删除政策须另行审定，不从本次部署推定。

首次写入须核对新鲜停止证明、原状态及账号代数，相同幂等重放只返回旧回执。封存记录和原
Run、事件均受数据库不可变约束保护，不能靠删除记录解除封存。没有普通用户或公网运维入口。

旧代码不理解新表与封存门，不支持直接回退并继续执行。必要回退使用已验证备份，保全新
审计、业务增量与证据，再由负责人决定恢复方式；不在本次操作中删除或降级封存事实。

该决定只定义实现与验收边界，不表示任何生产 Run 已完成停止证明、已封存或已经部署。
