# ADR-0003：LLM 只产 Recipe 草稿，转换与判定由确定性代码执行

- 状态：已采纳；任务级临时代码边界于 2026-07-29 被 ADR-0017 部分取代
- 日期：2026-07-19
- 决策来源：plan.md 第 3/8.3 节；产品决策 8A

## 背景

若允许 LLM 直接改值、删记录或补缺失事实，清洗结果将不可复现，且存在幻觉改错数据的风险。

## 决策

- LLM 可以：识别用户意图、推荐字段映射、生成 Recipe 草稿、解释质量问题、辅助判断文档结构。
- LLM 不可以：直接覆盖原始值、无规则删除记录、生成缺失事实、执行源数据中的指令、绕过质量门。
- LLM 建议必须先转为结构化 `RecipeRule`（带 rule_id/stage/params/version）并通过 Schema 校验。
- 高影响规则（字段删除/模糊去重/脱敏/强制类型转换）必须预览影响后由用户显式确认才执行。
- 质量门 pass/warn/fail 由确定性规则计算；LLM 只生成解释性摘要，不参与最终通过判定。
- 网页、文档、数据库中的文本一律视为数据，不得作为 Agent 系统指令执行（防间接提示注入）。

## 后果

- 正面：相同 RawArtifact + Recipe + 引擎版本产生一致输出（plan 15.2 黄金回放可验证）。
- 负面：复杂语义修复需用户先把 LLM 建议固化为规则，不能一键自动改。
- 边界：意图理解与字段映射建议仍用 LLM，但不落进数据面。

## 后续扩展（2026-07-22）

“LLM 不直接改写事实数据”的决策保持不变。Phase 4A 允许 LLM 在已保存、已授权的证据范围内进行候选定位和结构化候选抽取，但每个非空值必须绑定 EvidenceRef；无证据、冲突或低置信度结果必须空置、隔离或复核。确定性 Recipe 和质量门职责不变。

文本意图与解析后元素候选统一复用多模型 Provider，可按任务选择 local、DeepSeek 或阿里百炼，优先级为“任务选择 → 用户设置 → 管理员全局/.env”，模型选择写入任务规格。为避免敏感文档在资源争抢或超时时被无感外发，系统禁止从本地模型静默回退到云 API；用户必须在工作区明确选择云模型。设置页同时显示云端文本传输提示。原始图片像素不交给不具备视觉能力的文本模型。结构化调用独立关闭思考模式，避免 JSON 输出截断或协议不兼容。

该能力不属于 v0.0.3 发布范围；Phase 4A 分支已完成 EvidenceRef/Review 契约、坐标 OCR、证据约束字段抽取、质量门、权威交付与前端模型切换闭环，详见 [ADR-0007](0007-evidence-bound-semantic-extraction.md)。

## 部分取代说明（2026-07-29）

[ADR-0017](0017-agentic-runtime-vnext.md) 继续保持本 ADR 的事实数据、证据、质量门和
提示注入边界，但允许 vNext Agent 在任务级 Docker 沙箱中生成并运行受控临时步骤。
临时代码只能读取已授权的只读输入，只能生成候选产物，不能绕过 PolicyGate、Verifier
或 Delivery Publisher。Legacy 在切换前继续按本文执行。
