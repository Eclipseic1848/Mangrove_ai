## 问题诊断

| 症状 | 根因（代码层面） |
|------|------|
| 数据爬取不到 | ① 中文强反爬站正文抓取只有 Tavily/mediacrawler 能过；② 代理池只有框架未实测；③ browser 兜底写死只采 3 条 |
| 意图理解偏差 | ① intent→planner 双 LLM 松散 JSON，弱模型误判无校验；② 无意图评测集，改 prompt 无回归保障 |
| 数据不全不准 | ① collect 节点 `has_data` 即停——只采到 1 条也不再降级补采；② 无内容质量过滤（验证页/乱码混入）；③ 发布日期解析弱 |
| 模板调用错误 | 路由靠硬编码信号词表（`_VOC_INTENT_SIGNALS`/`_ANTI_SIGNALS`），词表外表述必然漏判/误判 |

## P0 — 直接影响可用性

- [x] **P0-1 采集量不足自动补采**（2026-07-03 交付）：collect 节点对关键词发现型任务（无显式 URL）在数据量 < max_items 的 60% 时继续用下一采集器补齐，跨采集器按 URL 去重；URL 任务不补采（各引擎抓同一批 URL 无意义）。`collector_used` 多引擎时为 `a+b` 串。测试 `scripts/test_collect_topup.py` 5/5。
- [x] **P0-2 内容质量门**（2026-07-03 交付）：clean 节点新增验证页特征检测（短正文命中"安全验证/403"等词）+ 乱码检测（替换符占比>15%），剔除统计进 `state.clean_stats`，白盒卡片透出剔除原因。测试 `scripts/test_clean.py` 6/6。
- [x] **P0-3 意图评测集**（2026-07-03 交付）：`scripts/eval_intent.py` 16 条黄金样例（真 VOC/伪 VOC/招投标/新闻/商品/平台识别/澄清），真实调 LLM，通过线 80%；deepseek 基线 16/16=100%。改 intent/planner prompt 必须先过本评测。
- [x] **P0-4 模板路由 LLM 化**（2026-07-03 交付）：`analyze._select_system` 升级双通道——词表信号 + 小 LLM 分类（`_classify_route_llm`，强领域 data_type 已确定时跳过省调用；失败回退纯词表）；LLM 判 voc 可补词表盲区、判强领域可修 generic 误判，但不劫持评论/帖子数据（保留自学习）。路由依据进 `state.analysis_route` 白盒透出。测试 `scripts/test_analyze_routing.py` 13/13。

## P-采集器补强 — 让采集免疫 VPN 开关 + 补强反爬（2026-07-03 交付）

> 核心诉求：无论本机 VPN 开没开，都能采到公域数据（Agent 最重要的前置能力）。

- [x] **P-A 网络智能分流**：`_net.py` 新增 `smart_client(url)`/`is_overseas`/`probe_network`。国内/本地/未知域名强制直连（`trust_env=False` 绕 Clash 系统代理劫持），仅境外服务走代理——采集与 VPN 状态解耦。article/simple_http/search 全部改用。测试 `scripts/test_net_routing.py` 5/5。
- [x] **P-B Camoufox 隐身兜底**：scrapling 采集器 Fetcher 取空时用 `StealthyFetcher`(Camoufox 隐身浏览器)重抓强反爬站。**实测抓到知乎正文 6859 字**（记忆里 httpx/crawl4ai/firecrawl 全失败的站）。开关 `SCRAPLING_STEALTH_ENABLED`，需 `scrapling install`，内核不可用自动降级。
- [x] **P-C Bing 免 key 搜索后端**：search 终极兜底加 `bing_html`（www.bing.com+cookie，国内直连、免 VPN、Google 的直连替代），实测发现真实链接。评估结论：agent-search 是 SearXNG 再包一层（重复不接）、4get 需额外部署（增量有限）。
- [x] **P-E 采集器全面审计 + 修复**（2026-07-03）：11 采集器逐一验证。① ecommerce/rss/site_crawler 补齐 smart_client 分流；② 删 ecommerce 3 个死代码函数；③ ecommerce.matches 诚实化（只认京东，淘系不接管）；④ mediacrawler 超时改读 settings；⑤ 强反爬站短路（`registry` 让 scrapling/Camoufox 对 `ANTI_SCRAPE_DOMAINS` 提前，跳过注定失败的 firecrawl/crawl4ai）。
- [x] **P-F RSSHub 采集器**（2026-07-03）：新建 `rsshub_collector`（tier 5），把无官方 RSS 的站转标准 RSS，微博/什么值得买等关键词轻量采集。采集器增至 **12 个**。
- [~] **P-D 字体反爬破解**（汽车之家等 CSS @font-face）：**暂缓·按需触发**（2026-07-03 用户定）。Camoufox 渲染后 DOM 文本仍是映射乱码，需按站维护字体映射表/OCR，工作量大、单站专用、易随对方改版失效，投入产出比低。真遇到某站字体加密卡住时再针对性做（先锁定单站）。注：汽车之家资讯/文章正文 Camoufox 已能覆盖，字体反爬主要卡论坛帖少量关键字。

- [x] **P1-3 发布日期解析增强**（2026-07-06 交付）：`_recency.py` 新增 `extract_date_from_html`（meta 标签[article:published_time/pubdate 等 18 键，属性顺序无关]→ JSON-LD[datePublished/dateCreated/uploadDate]→ `<time datetime>` 三路），由 `_extract.extract_content` 在剥 HTML 前调用回填 `metadata["date"]`（三条提取路径全接）；`_parse_date_str` 补相对日期（刚刚/N分钟前/N小时前/今天/昨天/前天/N天前）与无年份日期（"07月05日"、微博式"07-05 12:30"须带时间防误认，跨年自动回退）。测试 `scripts/test_recency.py` 8/8（含布线验证）。
