# #133 已批准工具复用

## 目标与输入

在既有 CapabilityCatalog → Governance → MountResolver → CapabilityHost 链上复用精确工具，不另建插件市场。工具需求使用明确的操作及输入/输出格式；描述只用于本地解释，公开候选检索只发送用户确认的通用工具需求。

允许输入：当前 Owner、任务修订、冻结 pack/version/digest、已批准能力包内的兼容契约及来源/许可证声明。能力兼容契约复用 CapabilityManifest，放入不可变包 manifest 的 `reuse_contract` JSON 字段，许可证为 `license` 字段。缺少声明的旧包保留原显式选择入口及既有 Pi 路径；新 CoreMind 工具合同须有正向业务契约，不允许手选绕过。不能把旧包自动匹配称为兼容。

## 要求输出

- 优先返回已安装且通过原新任务治理门的精确能力、兼容依据、来源/许可证与修复处方；不把目录可见或历史验证称为本次健康检查。
- 本次真实健康由既有 Host 启动门验证，成功后才能调用；工具选型与冻结身份保留在任务能力选择及事件中。
- 未命中才允许有界公开候选检索；候选不足的许可证/精确版本/摘要明确列缺口，不自动下载、安装、晋级或平台发布。
- 所选 CoreMind Adapter 经自己的注册工具桥调用同一治理宿主；不偷偷改选 Pi，不让模型指定 Shell 或任意宿主路径。

## 实施接缝

1. 复用能力包兼容契约与既有灰度 API/冻结选择。普通用户不能借管理员受众使用平台包；权限不扩大。
2. CoreMind 维持无扩展工具的原合同；启用工具的独立固定合同增加受限调用。两种合同在 Run 启动前选择并冻结，历史恢复按冻结 digest 选择，禁止启动后改变合同。
3. Adapter 装载、启动、恢复和取消管理原 Host 租约；当前网络保持禁止。Owner、冻结版本、工具注册、参数及返回大小必须核验；unknown 不能自动重放。

业务调用前再次解析冻结挂载并过治理/完整性门，再按实际运行清单对应包校验 `reuse_contract.parameters_schema`。原生 python/node/cli 的 schema 根类型为 array，MCP local 为 object；MCP 还须由不可变 manifest 的 `reuse_tools` JSON 字符串数组显式批准工具名。当前 schema 只接受包内直接声明、不接受引用，避免隐式外发与递归失控；Schema 校验复用已安装 jsonschema。此声明不代替原验证/晋级链。

工作台复用入口基于工具卡片已有兼容声明，由用户显式确认，使用当前上传/交付格式匹配；没有可信操作及格式时提示补全，不靠 query 关键词假称语义理解。修改来源或输出后必须清除旧匹配，任务创建再次复核。

## 验收标准与边界

- 第一个任务保留可复用身份；第二个相同兼容需求的任务命中既有工具，零额外发现请求。
- 不兼容、撤销、隔离、失效、Owner 或受众不符拒绝并提供修复提示；临时脚本不自动入目录。
- 一个已装真实能力以合成固定样本经所选 Adapter 验证调用、取消和恢复；Host 替身测试与真实验证分别报告。
- 受影响兄弟路径、永久红绿回归、Standards/Spec 与最终同提交 CI 通过后才能关闭。
- 不新增依赖，不编辑 CoreMind 专属 checkout，不改变生产数据库、秘密或既有服务。新增工具仍需明确安装批准；Docker 未运行时不能假称真实宿主验收通过。
- 主会话 Astra medium；前端相关工作 Astra high，其余委派 Astra low。Ponytail 管最小正确实现，Caveman 仅管表达。
