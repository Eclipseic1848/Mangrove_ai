## 1. 这次不是换皮

造成割裂的双工作区、模式切换、两层常驻侧栏、表单优先的启动方式或固定流程展示。

设计记录，与这次产品方向存在冲突。本轮不伪造运行时 Token 已变化；UX01 产出可交互原型并记录
用户视觉反馈，UX02 实现时同步修订 DESIGN 的布局/字体约束和运行时共享组件，不能静默混用。

## 3. 视觉论点和方向

推荐方向 A：**任务案头**。用户在一张案头上提出问题、摆放资料、核对结果；对话连续且易读，
资料和结果可随时摊开。品牌的可信感来自来源链接、数据定位与可追溯记录，不靠光效和装饰。

备选方向 B：**报告编辑台**。结果画布优先，对话收为侧栏；适合长报告审阅，但新任务和不明确
需求的起点较弱。因此 B 只作为 A 内部的“专注结果”布局，不增加第二种任务或运行模式。

建议布局：

```text
桌面：一个可收起的任务导航 | 当前任务、模型、状态、用量
                         | 连续对话      | 按需打开的资料/结果画布
                         | 简短工作记录  | 原件、表格、报告、来源定位
                         | 统一输入区    | 展开/专注/下载
窄屏：任务导航按钮 + 标题 | 对话 / 资料 / 结果（同一任务的视图，不是执行模式）
                         | 当前视图及持续可见的待办 | 可达的统一输入区
```

- 空任务只给简洁问题、统一输入和少量真实可用示例；不用巨大 Hero、双侧栏空白或三步卡片墙。
- 默认中央对话，右侧按需要打开，不强迫三列同时出现。宽表/报告可专注查看并返回原滚动位置。
- 主色保留红树林青，强调使用现有浅青；红/黄等只表达语义状态，同时配文字。不为页面复制色值。
- CSS HSL 变量仍是运行时 Token 权威。原型测定密度、行宽和字号后再更新 DESIGN，不能只改文档。
- 最多两种字体。建议优先验证中文等宽观感良好的正文与单一技术 mono 配对；不再以 Inter 作为
  视觉默认答案。新字体涉及下载/依赖时先核验许可证与授权；初始原型可用本地中文字体做对照。
- 平面分隔、适度留白、少量边框；只有浮层需要层次阴影。长文不放聊天气泡大卡片；表格不过度圆角。
- 微交互 150–300ms，尊重 reduced-motion。保留可操作滚动条，禁止用 overflow-hidden 掩盖溢出。

## 4. 一套完整用户旅程

| 环节 | 用户看到什么、能做什么 | 不允许发生 |
|---|---|---|
| 开始 | 用自然语言描述；可附文件、网址、本人已有数据；模型直接可见 | 先要求选择文件/网页/旧报告或 Runtime |
| 不明确 | 展示对已有资料的具体发现，问一个关键问题；可补充原输入 | 固定业务问卷、连续技术追问、编造目标 |
| 获得数据 | 每个文件/来源的真实进度、错误与预览；可取消单项，其他有效资料保留 | 把搜索摘要冒充原文，假报固定百分比 |
| 登录/授权待办 | 对话中醒目的扫码或范围确认；处理完回同一任务 | 待办藏在折叠日志；借其他用户 Cookie |
| 执行 | 正文和工作记录分层；默认收起的动作摘要；停止/下一轮输入始终可达 | 原始思维链、伪造已执行工具、断流即重跑 |
| 检查结果 | 回答摘要、来源链接、原件/表格/报告预览、格式下载、版本与缺口 | 下载与预览不对应；9/10 条就隐藏所有结果 |
| 继续加工 | 同一输入区追加要求；保留旧版本；对指定结果或资料继续提问 | 覆盖旧结果或静默重新采集 |
| 复用 | 从任务资料或历史选择本人原始数据/加工结果，明确身份与获取时间 | 派生结果冒充原始事实，默认跨 Owner 分享 |
| 删除 | 显示实际关联任务与后果；独占、保留共享、删除共享的正确分支 | 只删列表假称清理完成；受影响运行继续读 |

工作记录只展示实际发生的动作、工具名称/用途、安全判断摘要、产出、失败和恢复。等待、取消请求、
实际停止、执行结束与正式交付分开。用户上翻后不抢滚动，提供“回到最新”；流式中文分块、Markdown
未闭合、重复/迟到事件和重连都须验证。任务/修订切换后的数据缓存必须绑定真实身份。

每个 Session 显示时间戳、阶段耗时、模型和 Provider 原生 Token 用量；缺失记未知而非 0。
自带 API Key 同样统计，界面只展示连接标识，绝不展示 Key。官方价可匹配时显示“参考费用”及
来源/核验日，不升级为收费账本；前置澄清、搜索规划与 Run 汇总必须去重。

## 5. 组件与实现边界

优先复用 React Router、TanStack Query/Table/Virtual、Radix Dialog/AlertDialog/Collapsible、
react-resizable-panels、react-dropzone、react-markdown、react-pdf、OpenSeadragon、Sonner、
Lucide 和 `components/ui/`。已安装不等于功能已通过验证；先找规范所有者，勿复制第二套组件库。

统一 UI 只投影 SemanticTaskLifecycle、SourceSnapshot、TaskRevision、WorkSession 和 Delivery；
不建立“新版聊天专用后端”。前置请求身份由 RT01 先定义。共享设置、模板、记忆、自动任务和管理
页面使用同一导航与基础控件，但不为样式调整改变角色、审计或业务数据语义。

跨页行为见根目录 `UX-CONTRACT.md` 草案。UX01 在原型中核实所有者，UX02/UX05 按实际接线更新。
验收完成前不能删除仍承担唯一功能的旧路径；不做历史任务迁移，也不处置真实历史数据。

## 6. 交付顺序与验收

1. UX01 与 R0 修复可同时准备：现状与能力矩阵、交互原型、两个主题及宽窄屏；由用户看真实操作后
   确认视觉方向，不以本蓝图或一张截图代替确认。
2. RT01/RO01 先明确运行前身份与外部只读边界；UX02 实现统一导航、输入和文件任务完整链。
3. UX03/UX04 实现工作记录、多轮修订与来源/结果画布；其余来源、混合、复用、登录、删除工单
   必须同时接入这些规范组件，不能只交后端 API。
4. UX05 统一辅助页面；QA01 用完整真实代表任务及安全条件做总体验验收。
5. CLOSE01 在能力矩阵全部核对后退役双入口和过期代码/文档；不增加永久双栈。

每个界面工单必须包含加载、空态、部分成功、错误、取消、重连、权限拒绝、长内容、中文 IME、
键盘、窄屏、明暗主题与 reduced-motion 中适用的状态。宽屏和 390px 的输入/停止/预览/下载均可达；
还应验证 200% 缩放及短视口，不能以 body 没横向滚动代替内容可见性。代表任务成功、用户视觉认可、
自动测试绿色分别记录；有任一缺口就不能宣称最终体验完成。
