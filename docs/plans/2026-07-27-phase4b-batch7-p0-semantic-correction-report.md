## 1. 事故与可追溯证据

Word 逐字转换为 TXT。该结果虽然通过了旧版证据一致性检查，但没有满足用户限定的
业务范围，属于“技术检查通过、业务语义错误”的假成功。

“商务条款有哪些”被正确理解和完整执行。尤其是用户回答“整份文档”时，系统仍可能

## 2. 根因

这不是单一提示词问题。第一次纠偏识别了五层范围契约缺口，但漏掉了四个更深层根因：

1. 用户回答澄清问题后，工作台只把回答拼成“用户补充”再次交给模型，没有结构化携带
   上一版计划；第二轮模型漏掉的 `section_patterns`、选择和结果粒度因此静默消失。
2. `extract` 计划没有要求“限定章节/概念/页码”或“明确全文”二选一。
3. Binder 在零语义引用、零绑定时仍可返回 ready。
4. 文档物理计划和执行器把“没有选择”解释成“处理全文”。
5. 文档校验器只验证引用是否逐字回绑来源，没有验证输出是否遵守用户限定范围。
6. `whole_document` 同时承担“扫描整份来源”和“交付整份原文”两种相反语义；用户说
   “整份文档”只是回答搜索范围，却被解释成全文输出。
7. 宽泛概念查询先经关键词模糊匹配、向量召回或重排缩小候选，真实商务条款没有统一
   字面词，导致验收、保密、知识产权、服务和违约等分散章节无法完整进入候选集。
8. 模型分批分类存在字段漂移、ID 缺失和不一致，旧代码没有对完整候选 ID 集失败关闭。
9. TXT 渲染按 passage 重复写同一个查询标题，产生大量噪声，降低结果可读性。

旧测试主要验证单轮 happy path、格式可打开和证据正确，没有覆盖
“多轮澄清后范围丢失 → Word 限定提取 → TXT 正式交付”的完整链路。

## 3. 修复后的强制契约

### 3.1 多轮语义不可丢

- `CompileRequest` 新增结构化 `prior_plan + clarification`，两者必须同时出现；
- 回答必须对应上一版计划中真实存在的 `ambiguity_id`；
- 编译器把上一版计划和本次问题/回答同时提供给语义生成器；
- 新草案省略或无关地改写范围、选择、粒度、操作、交付格式或后置条件时，保留上一版
  无冲突约束；只有当前澄清问题明确询问输出/格式时才允许改变交付格式；
- 已回答歧义固定写入 `resolved=true + resolution`，即使模型再次返回同一问题也不会重复追问；
- 如果用户明确要求“全文转换/原样输出”，才允许全文输出覆盖旧章节范围；
- 如果澄清问题问的是“在哪些章节/页码内查找”，回答“整份文档”只扩大**搜索范围**，
  保留内容选择条件，绝不能切换为全文输出。

### 3.2 全源搜索与全文输出分离

- `SourceScope.whole_document` 只表示用户明确要求全文转换/全文处理；
- “从整份文档找出商务条款”编译为 `content_query`，对全部结构元素逐一判定；
- Binder 不再用模糊匹配或 rerank top-k 预先裁掉语义候选；
- 每个来源元素都使用短 ID，并要求分类结果对 ID 集完全覆盖；缺失、重复、未知 ID 或
  不确定结果一律暂停/失败关闭，不能默认为匹配或全文；
- 非宽泛内容查询复用 Instructor 结构化本地模型分类，不静默外发；
- 宽泛合同/商务问题使用结构上下文与确定性规则识别费用、服务、交付、验收、保密、
  知识产权和违约等内容，并排除产品功能、技术参数、目录和标题噪声。该规则只作为
  通用 `content_query` 的一个有边界领域策略，不改变表格、比较、审查等主链。

### 3.3 限定提取失败关闭

- `extract` 必须至少具备章节/概念、页码或选择条件，否则编译最多修复两次后失败；
- `whole_document` 不得与章节、页码或选择条件并存；
- Binder 对无范围、无引用的限定提取直接拒绝；
- 页码范围会编译成真实 `DocumentSelection`，不退化为全文；
- 原文物理计划必须是“显式全文”或“至少一个绑定选择”；
- 执行器遇到两者皆无时抛错，不再默认读取整份文档。

### 3.4 正式交付前验证业务范围与可读性

新增确定性检查 `document_scope_respected`：

- 限定结果的 passage 标签必须对应物理选择；
- 每个 passage 至少包含一个属于该选择的绑定来源元素；
- 把全文结果伪装进限定计划时，即使逐字证据全部正确，也固定验证失败；
- 验证失败时 `authoritative_output_allowed=false`，不得发布正式下载。
- TXT 中同一选择标签只输出一次，相关原文按来源顺序聚合，不再为每一段重复问题标题。
