## 1. 语义计划编译失败

真实任务 `workspace_1c873bb22bc44ef4` 要求识别并汇总 Word 中的商务条款。
任务于 03:10:07 创建，03:25:16 失败，未进入来源读取、Binder、Harness 或正式交付。

持久化诊断记录了三次编译尝试：

1. 第一次本地 `Qwen3.6-35B-A3B` 结构化输出达到 `max_tokens` 上限，被截断；
2. 第二次仍因相同原因被截断；
3. 第三次生成草案，但缺少每个 selection 必须具备的
   `required_ratio=1.0` 谓词后置条件，静态校验失败。

当前代码边界：

- 语义编译器直接使用 Instructor/OpenAI 客户端，没有显式传入 `max_tokens`；
- `.env` 的 `LOCAL_MAX_TOKENS=32768` 只作用于统一 Provider 聊天模型路径，没有作用到
  该结构化编译调用；
- `LOCAL_ENABLE_THINKING=True` 仍被透传给结构化任务，增加输出预算耗尽风险；
- 两次修复预算耗尽后没有形成可回答的澄清问题，工作台只显示通用失败文案。

`docx + pdf`。该错配不是本次编译失败的直接原因，但即使后续执行成功，也可能造成
交付格式偏离用户要求。

## 5. 新增：PDF 文档表格转 CSV 的结构性失败

2026-07-29 真实任务要求从 PDF 附件 2 中抽取“服务费用标准及明细”，只输出一张 CSV，
其余内容不要。系统没有完成目标，而是寻找不存在的 `content` 字段，并显示“需要确认
一项信息”的弹窗。弹窗只有关闭入口，没有修改目标、重新扫描/OCR、扩大来源或停止任务
等真实操作，因此对普通用户没有帮助。

代码复盘确认：

- 语义计划先于真实来源检查；
- `TaskFamily` 二选一决定整个执行能力；
- 文档执行器拒绝表格任务；
- 表格执行器拒绝文档来源；
- 因此“PDF 文档里的表格 → CSV”在 Legacy 中是结构性死路。

该问题不得通过当前用例专属 Prompt、Skill、关键词或 `TaskFamily` 分支修复。用户已批准
建立 Agentic Runtime vNext 专项，以不可变 Goal、来源观察、动态工具组合、任务级沙箱、
独立验证和双轨灰度根治。阶段 1 没有候选直接通过生产硬门；用户随后批准并授权完整
Pi RPC + 任务级 Docker 的全能力生产灰度纵切面。OpenCode 保留后备，原
LangChain/LangGraph fallback 不再执行。
