## 1. 目标

同一个精确 digest 的全部必要证据通过时，系统确定性把它从 `draft` 晋级为 `verified`；
任何缺口都保持 `draft` 并可解释。

## 2. 范围

1. **晋级判定门**：五步验证全部 `succeeded` + 供应链证据 `passed`（含 Trivy 漏洞库未过期、
   证据 hash 复核）→ 晋级；否则保持 draft。
2. **晋级命令**：幂等（同键只产生一个晋级结果）、带预期状态（只能 `draft→verified`）、
   并发冲突不以最后写入覆盖。
3. **治理事件 + 投影重算**：追加晋级事件，投影层按事件流算出 `verified`；新 digest /
   新 version 是独立验证事实，不继承旧 `verified`；失败记录不可覆盖。
4. **缺口展示**：Owner 看到"已验证"或脱敏的具体缺口；看不到内部路径、命令、Token、
   原始扫描日志。
5. **测试**：Python Tool 与 MCP 冻结夹具各覆盖成功/失败路径，不用实现自己的摘要证明自己。

## 5. 状态转移

- `register_pack` 只能建立 `draft/active/eligible` 初始态（现状保持）。
- 新增唯一转移：`draft → verified`，条件 = 五步全过 + 供应链 passed + 漏洞库未过期；
  任何缺口、部分通过、扫描器异常、过期库、hash 失配 → 保持 draft。
- 成熟度单向：没有 `verified → draft`。
- 生命周期（`active | deprecated | revoked`）与运行资格（`eligible | quarantined`）不受
  本次晋级影响；三轴正交，各自留给 #14/#13。
- 失败运行不可覆盖；旧 verified digest 与冻结 TaskRevision 不因新版本失败而改变
  （现有不可变结构已保证，晋级门不引入例外）。

## 6. 权限矩阵

| 角色 | #10 之后能做什么 |
| --- | --- |
| Owner | 发起验证；看自己能力的"已验证"或脱敏缺口；不能看内部路径/命令/Token/原始扫描日志 |
| 管理员/超管 | 跨 Owner 治理投影只读（现状保持）；#10 不新增管理员动作（审核是 #11） |
| 普通用户 | 看不到他人能力与验证（现状保持） |
| 晋级动作本身 | 系统执行（CapabilityGovernance 内部命令），任何用户角色都不直接触发 |

## 7. 缺口展示

服务端提供脱敏缺口枚举（例如"缺真实任务重放证据 / 供应链扫描未通过：可修复 High 漏洞 /
漏洞库已过期"），API 与前端卡片消费；不返回内部细节。

## 8. 已确认决策（2026-08-14）

1. **晋级触发**：自动晋级。验证五步 + 供应链证据全过后系统确定性晋级，Owner 不需要第二次
   手动点击；发起验证时界面明示"通过后自动晋级"。
2. **触发时点**：验证运行终态落库、供应链证据落库两个时点各自触发一次晋级判定；
   幂等命令保证只晋级一次。
3. **数据库落点**：复用现有治理事件表 + 投影重算；若事件表幂等约束不足，纯新增幂等辅助
   结构，不做宽表改造。
4. **幂等键**：由 digest + 触发来源（验证运行 id / 供应链证据 id）推导；同键重试命中同一
   晋级事件，不同证据集产生不同键。设计阶段细化为 `promotion:{digest}:validation:{run_id}`
   （供应链证据 id 不进键），见设计文档 §3。

## 9. 验证策略

- 只在公共 Seam 断言外部可观察结果：投影状态、缺口、审计、权限；不测私有函数。
- 成功路径：五步 succeeded + 供应链 passed → 投影 verified + 晋级事件。
- 失败路径：单次任务成功、部分步骤通过、扫描器异常、过期库、证据 hash 失配均保持 draft；
  幂等重放只产生一个晋级结果；并发冲突 409 不覆盖；新 digest 不继承。
- 夹具：Python Tool 与 MCP 冻结夹具成功/失败双向覆盖；断言数据来自冻结夹具与既有证据，
  不来自实现自身。
