# 通用证据采集修复执行记录

本记录对应用户批准的中信权益任务复盘方案。滚动状态以 `docs/status/current.md` 为准；
决策见 [ADR-0048](../adr/0048-staged-evidence-collection-and-host-copy-drafts.md)。

## 已实现的共同流程

`冻结 query 与来源 → 发现候选 → 低成本筛选 → 按需读取评论／图片 → 抽取并关联原文 → 分离结果和审计 → 宿主初稿 → 用户决定`

| 问题 | 实现与边界 |
| --- | --- |
| 0 篇来源失败被当成成功初稿 | 公共结果判定区分 failed、empty、incomplete、partial、complete；严格要求不足不创建业务初稿，诊断文件仍可下载 |
| JSON／Excel 被交给文档工具 | 冻结目标清单按类型声明读取方式；文档工具仍只接受原有 PDF／图片授权，未扩大权限 |
| 原样文件复制也调用模型 | 宿主按完整格式合同和来源哈希复制，复用重开与初稿冻结门；等待用户决定，非正式发布 |
| 深读早于筛选 | 银行与通用主题共用 `collect_evidence`；发现关闭评论，先校验元数据与范围，再按需补评论、图片及完整字段 |
| 模型操作额度丢失 | bound 调用透传 max_tokens；四类 Provider 协议按操作预算与模型上限取小值，筛选与抽取分开 |
| 长节点中断重复工作 | 每批／篇私有持久进度，Owner／任务／冻结范围／模型连接／处理版本绑定；原件哈希校验，未知在途结果不重放 |
| 同 task_id 又重新规划 | Conductor 恢复使用原检查点输入，保留 TaskSpec；输入或执行身份变化拒绝复用 |
| 候选混入业务明细 | 业务表只包含 selected；候选审计保留所有记录，评论／图片／条目均带父状态和排除原因 |
| 引用存在被当成业务核实 | 非空字段须有逐字引用，仍明确 quoted_unreviewed；日期语义分开，共享图片按哈希列出来源关系 |
| 每个行业加一条执行流 | 通用主题冻结 queries、fields 和提取说明；银行仅保留领域筛选、字段及排序，图片读取已移至公共来源模块 |

当前新增的分阶段来源适配仅为小红书。酒店会员、商品优惠通过同一入口的合成来源验证；
不能据此宣称已验收其他平台或真实客户业务。当前计数单位为笔记，不支持把活动／权益条目数静默换成笔记数。

## 验证证据

- 定向回归涵盖来源失败／正常无匹配／严格与部分结果、四类 Provider 预算、跨主题共用流程、评论按需读取、日期语义、候选预算、发现中断、逐篇恢复、Owner 与模型变化、原件篡改、Excel 结果与审计投影。
- 宿主集成测试真实经过 `_start`／`_resume` 控制流，仅模拟外部容器及模型边界：复制不调用二者，未批准继续不执行，批准后同 Run 首次启动；消费后缺会话或在模型可写目录伪造 pending 均拒绝恢复。
- 混合来源测试检查实际生成的 goal 清单，JSON／XLSX 与 PDF／PNG 读取方式不同。未调用真实模型证明其必然遵循清单。
- LangGraph InMemorySaver 验证公开 `run_conductor`／`astream_conductor` 同 task_id 中断续跑不重规划，变更 Owner 拒绝。
- 集中回归原始记录：`logs/task-type-fix-20260924/combined-before-fixture-fix.xml`；临时库授权夹具修正后的受影响回归为 `fixture-regression.xml`，逐用例最新结果汇总为 `verification.json`。最终计数与运行边界登记在当前状态台账，避免在多处重复滚动状态。

## 双轴审查

- 基准为本轮修改前的 `before.zip` 和 `before-sha256.json`，未把已有未提交工作算成本轮差异。
- Standards 首轮发现宿主复制资格处于模型可写目录；已移入未挂载的宿主目录，永久消费并补回归，复核通过。
- Spec 首轮发现候选预算按去重数扣减、图片恢复未验哈希、发现未持久占位、评论和图片缺父状态；均已修复并补回归，复核通过。
- 两轴结论是只读代码审查，不是生产或真实模型验收。
- 集中回归暴露 6 个旧初稿接受用例未绑定临时库授权校验，会读到其他测试缓存的 API Store；只修测试上下文，使用既有 `execution_validation` 绑定本库，未放宽产品权限或绕过校验。
