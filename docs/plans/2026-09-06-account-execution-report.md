# Issue #116：账号停用与执行授权

账号停用或转为待审批后，新动作和旧授权的迟到提交立即拒绝。已有执行只有在确认资源静默后才完成收口；重新启用账号不会自动继续历史任务。

## 实现与边界

- 单调账号执行代数、固定八类持久绑定及停用操作，覆盖工作台、数据任务、Harness、来源、验证、聊天、候选和调度。请求冻结原授权；恢复读取原绑定，缺失绑定失败关闭。
- 创建、领取与结果提交在原事务内复核 Owner 和代数；线程池真正开始、工具/Provider 调用、等待返回和正式交付提交均有安全点。取消等待真实线程结束，未知外部结果不自动重放。
- 管理页分别展示账号状态与收口的处理中、完成、失败，支持同操作重试。工作台保留问题、来源、checkpoint 和旧正式交付；未启动或等待任务显式恢复原流程，已硬停 Runtime 通过新 Revision 重新执行。
- 调度领取核对冻结快照；停用事务撤销旧 Provider Grant。HITL 动作只领取一次，签名异常保留未知资源状态。崩溃遗留发布 intent 取得原锁且确认没有正式交付后才中止，保留文件证据。
- 独立评测与文档 Relay 使用明确数据库及原授权，不借用产品默认数据库或凭证；历史冻结 G1 资格不因此更新。

新增 `webui_0012` 显式迁移；启动不迁移、不补绑。历史 Scheduler 回填须按
[回填规程](2026-09-06-account-execution-scheduler-backfill.md)核对配对快照、摘要、静默与恢复点。
仅在临时虚构数据库验证前向、重放和恢复；生产迁移、真实账号变更、Provider 认证、部署与发布仍需独立授权。

## 验证与完成门

局部验证已覆盖停用/待审批、重新启用、并发领取、迟到结果、多 Owner、重启、真实线程等待、签名未知状态和发布崩溃恢复。新增账号组合 189 项通过，完整隔离浏览器 165 项通过，均无跳过；前端类型检查与构建通过。Standards 与 Spec 由不同实现者交叉复核。

最终源码还必须通过 minimum-ci 三项与 `heavy-ci-manual / account-execution`：后者运行当前完整 Python 回归和全部隔离浏览器。唯一显式排除是 `test_independent_g1_dry_run_verifies_frozen_blind_set`，它检查历史冻结源码资格；原 `full-regression`、`g1-frozen-contracts` 及正式执行的冻结检查均保留。真实 Docker、外部数据库、性能与 CoreMind 实连等原有条件门的执行状态以 CI 报告为准，不计作通过。
