## 1. 本轮结论

本轮没有为“PDF 附件表格”“Word 商务条款”或“Excel 月份筛选”新增
`TaskFamily`、业务关键词路由或用例专属执行器。完整 Pi 继续在任务级 Docker
中观察真实来源、选择工具、生成候选；Mangrove 在 Pi 之外重新打开原件和候选，
形成独立验证报告。

已完成：

- 候选文件集合、数量、格式、来源身份和证据逐字匹配；
- 本地 Qwen 独立复核目标覆盖、明确不要和证据充分性；
- 验证结果持久化到 Runtime Run，并通过现有任务详情接口和 PC 深浅主题页面展示；
- 来源身份或证据失败时禁止候选下载；语义失败但来源可信时仍允许用户检查候选；
- 验证通过仍保持 `candidate_ready`，`formal_delivery_eligible=false`，不创建正式
  Delivery；
- Pi 在同一 RPC 会话中执行 `Verify → Replan`，最多三次有界修正；
- 使用 Pi 官方 Extension `tool_result` 钩子压缩大工具输出，保留定向读取提示，
  避免本地 32K 上下文被单次大表输出耗尽；
- 使用通用候选清单 CLI 逐条登记、删除证据并原子生成严格 JSON，规避本地模型在
  长 `write(path, content)` 工具参数中丢失 `content` 的问题。

## 4. 本轮发现并修复的通用缺陷

1. Pi RPC 的单条 JSONL 事件可能超过 asyncio 默认 64KB，真实 Word 首跑在传输层
   `LimitOverrunError`。RPC 子进程现在使用 8MB 有界流读取上限。
2. Pi 内置 Bash 虽会把单次输出截到 50KB，但多次大表输出仍会耗尽本地 32K
   上下文。当前使用官方 Extension Hook，把进入模型上下文的单条文本结果压到约
   6KB，并保留头尾和后续读取提示。
3. 本地 Qwen 生成较长 `write` 工具参数时会丢失 `content`。通用清单 CLI 将长 JSON
   改为短命令逐条登记，Pi 自带文件、Shell 和依赖能力保持完整。
4. 首轮 Runtime 只在 Pi 结束后验证，无法自动修正。现在每次 `agent_settled` 前执行
   候选预检和独立验证，失败原因回到同一会话，有界重规划三次。
5. Word 表格在解析器中使用制表符、工具展示常用 Markdown `|`。验证器只对结构
   分隔符做等价处理，避免把正确表格引用误判为伪证据。
