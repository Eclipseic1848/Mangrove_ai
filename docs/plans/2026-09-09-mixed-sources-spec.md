## 1. 目标

用户在统一工作台同一个输入区连续添加多个文件与独立获取的网页组，确认当前选中的完整来源集合，在一个任务修订内联合处理、查看证据及下载原件和正式结果。追加、移除或刷新某个来源不能悄悄覆盖其他已选资料；来源变化只在明确确认后形成新修订，不改写已冻结 Run。

沿现有 AgentKernel、所选 Adapter、模型连接、Verifier、Publisher 与工作台执行。多来源是同一来源集合的扩展，不新建混合专用 Runtime、另一套任务系统或独立资料库。

## 2. 允许输入与输出

### 2.1 允许输入

- 当前 Owner 已完成且可解析、可重新核验的 Upload。使用服务端保存的精确身份、类型和内容摘要，不以文件名或本机路径作为执行身份。
- 当前输入旅程中依授权取得的多个 SourceSnapshot。一个 snapshot 是一次获取的冻结结果，可含多个 Artifact；不同独立网址或查询可以产生不同 snapshot。每个快照独立保留访问范围、读取时间、正文身份和覆盖/失败事实。
- 用户原始任务要求、明确确认的字段/关联依据/冲突规则、输出格式，以及当前 Owner 已确认的 Context 与 preview hash。
- 已有任务当前修订的冻结来源集合，作为本任务新增修订的编辑基线；这不开放跨任务历史资料选择器。

仍只支持现有上传格式及 #134 的匿名公开网址/搜索范围。来源不可解析、Owner 不匹配、版本或 hash 漂移、治理或授权失效时失败关闭。搜索候选、页面摘要、执行日志、模型推测不得伪装成完整已读原文。

### 2.2 输出

1. 一个 TaskRevision 的完整冻结来源集合：上传与网页均进入规范化 refs，包含精确身份及其可追溯出处；逐网页组保留各自范围和覆盖事实。
2. 与该集合一致的运行输入。底层使用实际上传内容及冻结网页正文；不能仅把摘要交给 Runtime 后声称多来源处理。
3. 存在连接依据不足、同名实体不明或关键值冲突时，通过既有澄清/确认协议提出具体业务问题。用户确认前不自行选择关联键、覆盖顺序或填造缺失 ID。
4. 与实际来源对应的结果和证据定位。只有既有 QA、完整性及发布门通过的 `output_id` 才是正式交付；Candidate 不获得额外资格。
5. 包含所有选中原件、来源清单和缺口事实的完整资料包，沿 #132 既有派生格式规则导出。查看、重复下载不重新获取来源。

## 3. 来源集合合同

### 3.1 全量选择与身份

新创建与新修订均确认用户的**全量选择集合**。统一输入前端提交完整的 `upload_ids` 和 `source_snapshot_ids`，服务端先解析成最终全量集合，再原子冻结；文件分支和网页分支不得互相覆盖。修订 API 为兼容现有调用者允许省略某个类别：省略保留该类当前冻结引用，显式空数组移除该类。每个已提供数组都是该类的完整目标选择，不是仅追加项；合并后的全空集合不能启动任务。

旧纯文件、旧纯网页单快照请求保持兼容。旧修订请求中原有字段的缺省含义不能改变为“删除全部”。服务端应将旧请求显式归一到既有兼容语义，再进入同一冻结接缝；不能在新旧字段并存冲突时静默取其中一个。

去重只能针对相同精确来源身份：

- 同一个 Upload 引用重复出现，可以规范为一个条目；服务端重新核验 Owner、实际内容摘要和可用版本。
- 同一个 snapshot/Artifact 引用重复出现，可以规范去重；同正文但不同 URL、snapshot、授权范围或版本不得仅凭内容 hash 合并丢出处。
- 文件名与大小相同不代表同一份内容；前端不能在上传前据此吞掉用户选择。不同 upload 身份或不同版本不得因为展示名相同而被忽略。
- 页面列表顺序、文件拖动排序仅是展示顺序，除非用户明确提出业务规则，否则不等于冲突值的优先级。

服务端解析并冻结 refs 的完整身份。前端只提交 Upload/Snapshot 选择，不直接提交任意 Artifact/hash 作为授权。客户端提交的 Owner、hash、scope 或覆盖描述不能覆盖服务端事实；客户端用于恢复和预览的预期身份只能作为一致性校验输入。

### 3.2 网页组与覆盖

本票的网页选择和移除单位是**一次冻结获取对应的网页组**。精确网址通常是一页组，搜索/同站采集可能是多页组；独立获取 B、C 必须保留两个快照身份，不重新采集并合成共同快照或共同授权范围。

每组分别冻结 `allowed_scope`、coverage/search report、实际已读 Artifact、失败或越范围记录。任务整体可以汇总已读数量，但不能据此改写逐组事实：

- 本地表格完整，不能抵消网页“要求至少 10 页、实际 9 页”的硬缺口。
- 所选网页组的既有硬完整性门未满足时，不允许以增加文件或其他组方式绕过。
- 探索性部分来源可在明确披露缺口后使用，不声称全网、全站或目标资料已经完整。
- 结果实体数量、用户要求的记录数与来源文件数/网页数是不同概念，不自动互换。
- 用户从草稿移除一个组不删除它的原件或历史修订，也不自动改写任务文字中仍包含的数量/范围要求；后续确认需处理剩余目标与来源之间的缺口。

本票不要求在一次搜索快照内任意删页、拼页并重算该快照的授权/完整性。选择一个摘要用于预览不代表只选该页参与执行。

### 3.3 冻结与版本

冻结事务必须同时绑定最终来源集合、GoalContract、DeliverySpec、已确认 Context、模型连接版本、运行 binding 与必要外发确认。实际运行和正式发布核验都使用该冻结集合，不在中途读取草稿的新状态。

运行时上传与网页都必须按同一 TaskRevision 的冻结集合物化，不能上传取任务当前元数据、网页取历史 revision，从而混成两个时间点的输入。任务级投影变化、刷新或新修订不能改变旧 Run 的来源成员和正文。

持久化采用修订新增 nullable `source_contract_json`：保存与该修订实际来源集合绑定的 GoalContract 和逐网页组 scope/coverage；已存在的 runtime binding 与交付格式不重复存储。旧行 NULL 时读取原兼容合同，不修改旧冻结事实。字段通过新增 `webui_0016` 显式迁移建立；验证仅在隔离临时库进行，生产迁移另行授权。

移除最后一个网页组但仍保留文件时，新修订合同必须描述当前文件集合和用户已明确的目标，不能保留已移除 snapshot 充当非空外键锚点。旧纯文件请求不强加网页专属的数量/完整性必填字段；从混合移除网页不等于抹去用户原先明确的结果要求。

增加、移除、替换来源属于实质变更，沿已有确认新 TaskRevision 的协议生效。用户看到待确认完整集合；`expected_active_revision`、幂等身份、取消代数及执行状态门防止过期确认或并发写入。旧 Run 未静止时不能偷偷启动带新来源的 Run。

运行和恢复继续使用原 Adapter、Provider/模型连接版本及权限门。省略运行选择仍按现有平台默认路由；不能因为混合来源而强行指定某 Adapter，或从 Legacy/灰度拒绝中自动切换到另一个获准范围。

### 3.4 上下文、外发与工具复用

保留上下文选项的 Owner/版本核验和 `context_preview_sha256` 检查。混合来源的新增、移除、刷新或目标改变应使依赖旧草稿的确认失效，重新检查当前目标/最终集合及外发摘要后才提交；不能直接重用旧表单的“已确认”标志。

原文进入所选模型仍受既有连接、范围及外发确认约束。用户输入中出现网址不自动授权联网；来源采集与模型外发各自沿原有明确动作处理。

能力复用按最终来源集合重新核验输入/输出合同与治理资格。现有仅文件格式的复用合同不能因混合网页而自动扩充；不兼容应要求重新匹配或取消复用，不能悄悄去掉网页/文件以适配工具。

## 4. 最小统一输入旅程

### 4.1 添加与移除

同一个输入区保留任务文字、模型、输出格式及资料列表，提供现有文件入口和公开网页入口。已有文件不能使网页按钮禁用；打开网页添加区也不能让已有资料丢失或切入一个独立任务。

网页添加区复用 #134 的精确网址/查询、时间、域名、范围和用途表单。只有显式“获取网页/搜索并读取”才联网。获取成功把该快照加入当前草稿；继续添加另一个网址或查询产生新组，并保留之前文件/网页组。可先沿用一次一个网页获取，不要求新并行调度系统。

资料列表区分上传中、获取中、停止中、已就绪、部分结果、失败和待恢复状态。网页组标明本次网址/查询、范围、时间和已读/失败/未读计数；已读页面可看已保存摘要，候选仅标为候选。文件移除只取消当前草稿的该文件引用，网页移除明确为整组，不调用永久删除原件接口。

失败、取消或迟到的新获取不得移除其他有效资料；从草稿移除或取消后，旧响应不能重新追加到新草稿。新增失败项可保留原因供处理；使用其余资料时必须明确排除该项，不能在后台静默删掉失败来源。

### 4.2 单一提交点

最终由一个确认动作冻结当前完整选择，不保留“文件启动”和“网页启动”两套各自独立的目标、模型或集合。原输入、Context、模型确认和能力选择可以复用现有组件，不新增通用工作流框架。

已有有效来源时，输入与添加区来回、关闭摘要、配置模型返回均保留草稿。上传/获取/停止/unknown 项不能被伪装成已就绪来源；先确认其事实或明确不选用，再按有效集合和业务要求继续。硬不足按第 3.2 节拒绝。

冻结后补充继续沿当前任务编辑与确认新修订，不提供向旧 Run 任意追加来源的接口。冲突与缺关联依据沿现有对话澄清展示，不新增无条件要求用户配置全部连接规则的向导。

### 4.3 预览与导出

统一来源列表能定位每个已选 Upload 与每组下的实际 Artifact，不能只枚举第一个 web snapshot。任务形成后沿现有右侧预览、精确证据及资料包接口查看。网页摘要明确可能截断；完整原文沿资料包下载，不在本票新增全文预览 API。

保持桌面与窄屏、键盘/中文 IME、深浅主题和原文件预览的既有交互边界；展开采集、选择来源、关闭侧栏后焦点与已有输入可恢复。不能用横向溢出隐藏添加/移除/取消/确认按钮。

## 5. 取消与两类刷新

### 5.1 浏览器刷新与草稿恢复

浏览器刷新/重连恢复的是当前 Owner 当前草稿，不重新上传已完成文件或获取已保存网页。只保存所需 ID、元数据、预期摘要、选择顺序、目标/模型选择和获取幂等身份；不保存 File 对象、完整业务正文或凭据，不枚举跨任务历史来源。

- 已完成上传：以已有 Owner 隔离的 Upload 元数据 GET 重新核验引用。暂不可用保留明确待恢复项，禁止静默消失或以其他同名文件替代。
- 已取得 Attempt ID 的网页：恢复既有获取事实；已完成快照不再次采集。首响应未知沿 #134 原幂等身份和冻结条件确认，不能换新键重开相同获取。
- 未完成上传：当前 multipart 流程不能在浏览器刷新后恢复内存 File。本票保留原文件名/状态占位并提示重新选择该文件；不要求新增 multipart 幂等或断点续传系统，也不得宣称无重复自动恢复。首响应未知不能自动重传或伪造 Upload ID；再次选择应是明确用户动作。
- 取消、移除或切换 Owner 必须令旧响应失效；仍在等待的获取/任务创建不得覆盖新草稿。旧标签页不得以陈旧草稿代数覆盖已确认集合。

### 5.2 显式获取最新网页

“获取最新”必须指定一个当前网页组。按该组获准范围取得新 snapshot；成功后明确确认变化，以新修订替换该组，其他文件/组的身份和 hash 不变。范围扩大仍需明确授权；不能借刷新跨组扩大范围。

失败、取消、停止未完成、unknown 或并发修订冲突时保留原快照和原集合，不将部分迟到结果直接写入旧 Run。用户查看旧原文或重复下载不触发获取。旧单快照刷新仍兼容；面对多组请求缺少明确目标时不得默认刷新第一组。

## 6. 冻结接口与工程接缝

以下接口与持久化形式已经主任务选定。客户端发的是来源选择，服务端仍是精确 refs、授权和冻结事实的唯一权威。

| 接缝 | 最小建议与约束 |
| --- | --- |
| 创建输入 | 使用既有 `upload_ids` 与新增 `source_snapshot_ids`。旧 `source_snapshot_id` 与新列表互斥；两者同时提供明确拒绝，不静默优先。旧纯文件/纯网页输入继续兼容；规范化后总集合必须非空 |
| 修订输入 | `upload_ids`、`source_snapshot_ids` 均可省略；省略保留当前修订对应类别，显式空数组移除该类，显式非空数组替换为该类全量选择。统一前端提交两个完整数组，服务端冻结归一后的全量集合；最终集合非空 |
| 规范化与持久化 | 服务端解析 Owner、Upload、snapshot/Artifact、hash/版本及范围，原子冻结同一集合；已有 `source_refs_json` 优先复用，不允许网页分支覆盖上传 refs |
| 任务详情 | 返回可枚举的完整来源集合与逐网页组的 scope/coverage。旧单一 `web_source` 可作兼容投影，不能作为多来源唯一权威 |
| 上传恢复 | 复用现有 `GET /api/data-sources/uploads/{upload_id}`，不需新增历史上传浏览器或 multipart 恢复系统 |
| 获取恢复 | 复用已有 Attempt GET、冻结采集参数及同键事实确认；多个已选快照与当前在途 Attempt 分开保存 |
| 修订/刷新 | 全量目标集合与 `expected_active_revision` 等现有竞争门绑定。刷新采用 `target_source_snapshot_id`；当前多组时必填，单组时兼容旧省略调用。目标必须属于当前冻结集合，成功仅替换该组 |
| 请求结果恢复 | 新建与修订保留原幂等键及完整原请求；成功修订按实际回执恢复，准备中或结果未知不得换键重发。仅服务端确认未创建新任务/修订且没有未决准备、并已排除或安全释放原请求占位时的可信 rejected 标记允许修正重提，不能仅凭 409/422 或错误文案推断未执行 |
| 工具复用继承 | 来源或输出实质变化时，从当前 Owner/修订的实际冻结选择读取精确版本与经验证合同，核对新完整输入/输出兼容性；缺失合同或不兼容在准备前拒绝。事件缺失不代表未选择工具，无实变的既有继承保持 |
| 运行/发布 | 复用现有上传与网页共同物化的 sources 接缝，以及 QA/Publisher 对完整冻结身份集合的校验；验证失配要拒绝，不补读最新来源 |
| 数据库 | `webui_0016` 仅为修订表新增 nullable `source_contract_json`，与来源集合存同一修订；NULL 回退旧合同，移除最后网页不保留假锚点。在临时库核前向/重放/旧行兼容；不改旧迁移、不开隐式启动 DDL。生产迁移单独授权 |

已有预检确认的直接缺口包括：创建入口的来源 XOR、网页赋值覆盖上传 refs、修订替换整个集合、单快照 GoalContract/coverage 与单快照任务详情。不能只取消前端禁用或删除 XOR 就宣称混合已通。

## 7. 能变红的验收旅程

先固定输入、用户原话、预期结果及调用计数，再写永久回归。不得根据实际输出倒推预期。UI fixture、真实运行接缝、真实模型语义、真实搜索和正式交付资格分别记录，不互相代替。

### 7.1 预先固定的合成数据

- 表格 A：实体 `E-101`、名称“青林”，待补充字段“公开规模”。表格 D：不同实体 `E-202`、名称同为“青林”。两个表格分别含可区分的来源标记与冻结 hash。
- 独立网页 B：实体 `E-101`、公开规模 `200`。独立网页 C：实体 `E-101`、公开规模 `220`。B/C 有不同来源标记、URL、snapshot/Artifact 身份；默认没有用户指定优先来源。
- 无歧义用例：只选 A+B，用户明确“按实体 ID 补充公开规模”，预期 `E-101=200`，来源证据同时能回到 A 和 B。
- 冲突用例：选 A+B+C，用户尚未给冲突规则，预期先询问来源优先级；用户回答“以 C 为准”后才使用 `220`，保留 A/B/C 的身份及 B/C 冲突事实。
- 同名用例：加入 D，不能把 `E-101` 的规模填给 `E-202`。去掉可核连接键时，预期询问连接依据或明确未关联项，不按同名匹配。

### 7.3 真实语义验收与调用边界

源码实现与前端协作按用户既定模型路由执行；前端相关任务使用 Astra high。产品中 CoreMind/Pi 及其模型调用仍保持该任务所选 Adapter、连接版本和权限，不能为通过验收擅换运行路线。

真实语义验收先独立冻结第 7.1 节的合成输入、问题措辞、预期关联结果、冲突澄清条件和失败判据，再运行；不得让执行者根据模型返回改写期望。具体调用次数、超时、输出额度及停止边界由主任务另行确定，本规格不授权任何真实调用。

| 证据类别 | 需要独立确认的内容 | 不得据此声称 |
| --- | --- | --- |
| 工程接缝 | API、临时库、真实运行/QA/导出接缝，允许受控固定计划器/模型响应；逐项记录使用替身的位置 | 真实模型会自主关联、识别冲突或正确澄清 |
| 真实模型语义 | 预先冻结无歧义关联/冲突/同名缺键案例；按既有明确云 Provider 授权核准已批准端点、凭据作用域和本轮预算，沿所选 binding 执行并独立逐例审查 | 其他模型、未测范围、生产或全部业务场景均可用 |
| 真实公开搜索 | 沿 #134 原授权和安全边界单独记录获取成功/阻断与调用计数；不改变 DNS/代理/私网许可 | 冻结网页 fixture 证明当前环境真实搜索可用 |
| 正式交付/原件 | 核实实际 QA/发布状态、正式 output_id 与原件 bytes/hash；受控响应如何参与要明确 | 仅 Candidate、UI 下载按钮或假 ZIP 证明正式产出及原件完整 |

若使用云 Provider，必须核验已存在的用户授权是否覆盖目标端点/凭据作用域及计划中的调用，不从本票规格推断扩大授权。未知结果不自动重发；超预算或需要变更作用域时由主任务处理。工程结果和真实语义结果分别给出通过、失败、未执行或不可评，不拼接成虚假的统一通过。
