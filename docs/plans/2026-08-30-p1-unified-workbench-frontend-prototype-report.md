- 根 `DESIGN.md` 的视觉论点是“可信的数据工作台和证据接收单”，明确拒绝通用 SaaS 卡片墙、

  `SemanticWorkspacePage` 97.18 kB gzip。现有主入口超过 Vite 500 kB minified 警告线。
- 8088 与 5173 在本次核对时均未运行，因此尚无当前浏览器截图、交互或性能验收证据。

## 2. 已确认的视觉方向

采用“Grok/Codex 式工作记录 + Mangrove 证据工作台”，不是照抄参考图片，也不是改成通用聊天
页面。保留现有三栏职责：左侧任务列表，中间任务/结果主线，右侧来源和证据预览。对话能力进入
中间主线；智能体工作记录是正文中的单行折叠回执，扫码、授权、状态未知和接受缺口等用户动作
固定显示在折叠区外。

```text
任务列表 | 目标、回答、Candidate、Delivery       | 来源/证据预览
         | [需要操作：小红书登录已失效][扫码登录] |
         | ● 智能体正在检查结果 · 已完成 5 个动作 · 25 秒 [展开]
         | ✓ 智能体工作记录 · 12 个动作 · 用时 1分42秒 [展开]
```

展开后按发生顺序显示用户能理解、也能核对的事实：

```text
10:31 判断任务   需要读取指定来源并整理为表格
10:31 读取网页   调用网页工具 · 已取得 9 条可用记录
10:32 整理内容   调用表格工具 · 生成 9 行、7 列
10:32 检查结果   关键字段完整；全网覆盖范围未知
10:33 生成文件   已生成并重新打开验证
```

每一项可再展开一层经过脱敏的技术详情。这里的“判断”只显示运行时已经记录的决策摘要，绝不
展示或事后编造私有思维链。参考图片只用于确认“默认收起、按需展开”的交互方式，不作为像素级
视觉目标。

## 3. 与视觉方向无关的交互合同

1. 新任务只在 `/data-prep` 创建；来源选择、预览、对话和交付不得分裂为第二套生命周期。
2. 工作记录初始 `aria-expanded=false`。折叠态只显示真实工作时间、行动数、工具数、模型 Token
   和已处理重试数；展开后显示时间戳、判断摘要、工具、结果、证据和恢复记录，不显示私有思维链、
   Cookie、Secret、宿主路径或原始命令日志。
3. Cookie 确定失效时，同一 Run 暂停，页面主内容上方显示 OwnerActionRequest；二维码不得藏在
   工作记录内。扫码成功继续同一 Run；超时、扫码失败或服务重启后保持暂停并可获取新二维码。
4. 网络超时、平台故障或反爬只能显示“登录状态无法确认”，同时提供重新检测和扫码登录；不得
   删除 Cookie 或把状态误写为确定失效。
5. Candidate 明确标为待验证结果；只有 Delivery 提供正式预览和下载。工具安装范围、权限或
   外发提示使用用户语言，不暴露内部能力晋级术语。
6. 桌面保留任务列表和可开合来源预览；窄屏一次只显示主内容，任务列表与来源预览通过可访问的
   抽屉进入，返回后保持滚动、折叠和输入状态。

## 4. 实现完成门

### 组件与状态

- 复用现有 Radix Dialog、AlertDialog、Collapsible、Sonner、Lucide 和共享 Button/Input；不新增
  UI 框架，不复制第二套折叠、弹窗或通知组件。
- 覆盖初始、运行中、等待用户、状态未知、扫码中、扫码失败、已恢复、Candidate、Delivery、
  失败、取消和刷新/SSE 重连状态。
- 行动流式追加时不强制抢回用户滚动位置；折叠摘要和 OwnerActionRequest 从持久服务端事实恢复。

### 无障碍与响应式

- WCAG 2.2 AA；键盘可完成创建、展开、扫码、重试、取消、预览和下载；焦点可见且关闭弹层后
  回到触发控件。
- 状态不只依赖颜色；语义名称、`aria-expanded`、live region、错误关联和焦点顺序通过 axe 与
  浏览器检查。
- 至少验证 390px 窄屏和 1280px 桌面、深浅主题、200% 缩放、长中文、慢网、离线、SSE 重连和
  `prefers-reduced-motion: reduce`。

### 构建与性能

- TypeScript、Vite build、定向组件/Playwright/axe 和与改动相称的前端回归全部退出 0。
- #88 不引入新的 UI/动效依赖；`SemanticWorkspacePage` gzip 不超过当前 97.18 kB 基线 10 kB，
  除非真实功能差异和浏览器证据证明必要。
- 首个持久“已接收/正在处理”状态满足 ADR-0037 的 2 秒目标；流式追加不产生明显布局跳动，
  不使用假百分比或无限加载状态。
- Frontend Design Premium strict 审计中由本纵切面触及的错误必须归零；未触及的历史问题另列
  准确基线，不能用本工单顺手全站重构。

## 5. 已确认结论

- 已确认使用“智能体正在工作 / 智能体工作记录”，不使用会误导用户的“思考了 25 秒”。
- 已确认默认收起；展开后显示判断摘要、工具、结果、证据和恢复过程，并提供第二层脱敏技术详情。
- 已确认已恢复的失败仍留在明细中，收起态只轻量显示“已处理 1 次重试”；未解决失败始终可见。
- 已确认 WorkSession 等同于一个 Run；扫码等待、恢复和重试不另起 Session。每个 Session 显示
  时间戳、实际工作时间、模型调用次数与 Token；用户等待时间单独呈现。
- 已确认扫码登录、权限确认和数据外发等 OwnerActionRequest 位于工作记录之外，不能藏进折叠区。

## 6. 可抛弃原型与验证证据

原型位于 `.scratch/p1-01-anonymous-web-unified-workbench/prototype/index.html`，只验证交互合同，
不连接真实平台、不保存 Cookie，也不改动 `frontend/` 产品代码。

目标路径：工作台打开 → 工作记录默认收起 → 键盘展开并查看第二层脱敏技术详情 → 打开扫码
弹窗 → 关闭后焦点返回 → 模拟扫码成功 → 同一 WorkSession 恢复执行。

### 浏览器证据

- `agent-browser` 真实打开 `http://127.0.0.1:4177/`；标题为
  `Mangrove · 统一数据工作台原型`，页面非空，框架错误覆盖层计数为 0，console/page error 为空。
- 1280×800 与 390×844 均通过；390px 横向溢出差值为 0。640px 视口用于检查接近桌面 200%
  缩放时的重排，仍进入完整窄屏路径且无横向溢出；正式实现仍需补真实浏览器 200% 缩放矩阵。
- 浅色、深色和 `prefers-reduced-motion` 均真实渲染；深色背景计算值为 `rgb(14, 19, 22)`。
- Enter 将工作记录从 `aria-expanded=false` 切到 `true`，Space 可收起；扫码弹窗支持 Escape，
  关闭后焦点回到 `openQr`，恢复后焦点到 `ownerAction`。
- 移动端“来源”按钮打开模态面板；克隆内容不存在重复 ID，关闭动作可达。
- axe-core 4.12.1：桌面恢复态 `23 passes / 0 violations / 0 incomplete`；移动默认态
  `15 passes / 0 violations / 0 incomplete`。
- Frontend Design Premium strict：`0 errors / 0 warnings`；本原型反模式搜索为 0；UTF-8
  替换字符为 0。
