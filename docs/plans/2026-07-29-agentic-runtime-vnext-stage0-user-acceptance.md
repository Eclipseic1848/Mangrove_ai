# Mangrove Agentic Runtime vNext 阶段 0 用户验收说明

> 日期：2026-07-29
>
> 适用范围：只验收专项建档，不验收 Runtime 功能
>
> 预计用时：5–10 分钟

## 1. 这次应当看到什么

阶段 0 只把问题、目标架构、决策边界、评测方法和后续任务正式记录下来，并建立独立专项
分支与 GitHub 任务图。它不会修复当前 PDF→CSV 任务，也不会启动三种框架 PoC。

您需要确认的是“后续怎么改、用什么证据判断成功”，不是页面是否已经新增能力。

## 2. 验收步骤

### 第一步：查看专项结论

打开：

- [专项 Charter](2026-07-29-agentic-runtime-vnext-charter.md)
- [ADR-0017](../adr/0017-agentic-runtime-vnext.md)

确认以下内容符合您的要求：

- 不再为每种新问法添加点对点 Prompt 或业务分支；
- Agent 先看真实资料，再规划和选择工具；
- 文档、PDF、Excel/CSV 和混合来源属于首期范围；
- 临时代码只能在任务级 Docker 沙箱运行；
- 本地 Qwen 是强制门，外部模型不能替它通过；
- 验证失败不能发布正式下载；
- Legacy 保持默认，严格门通过前不替换；
- 服务器部署和最终实机验收继续后置。

### 第二步：查看如何判断候选框架

打开：

- [评测语料与赛马规格](2026-07-29-agentic-runtime-vnext-evaluation-spec.md)

重点检查：

- 当前“附件 2 服务费用标准及明细，只输出一张 CSV”是核心 P0；
- Word、Excel、扫描/数字/跨页 PDF、复合来源和未知问法均在门内；
- 每项用本地 Qwen 连续运行 3 次；
- 扩展泛化集至少 30 个，正确率不低于 90%；
- 安全、权限、用户隔离、禁止项和失败不得冒充成功必须 100%；
- 三条候选使用相同 Goal、工具、沙箱、预算和语料。

### 第三步：查看任务是否被拆清楚

打开：

- [任务拆分](2026-07-29-agentic-runtime-vnext-task-breakdown.md)

确认阶段顺序是：

```text
建档 → 三路线赛马 → 控制面 → 工具与沙箱 → 动态 Loop 与前端 → 影子和切换
```

并确认每个阶段结束后都要先向您展示产物和未决问题，不会自动进入下一阶段。

### 第四步：检查 GitHub

在仓库中检查：

- `v0.0.6` 包含本次文档提交；
- 存在 `feature/agentic-runtime-vnext` 分支，且从同一文档提交建立；
- 有一个 vNext 总 Issue；
- 总 Issue 链接调研赛马、领域契约、工具目录、沙箱、动态循环、上下文与 Skills、
  前端事件、评测切换和 Conductor 迁移子 Issue；
- Issue 明确写着后续阶段尚未开工。

### 第五步：确认没有越界实现

本次提交的文件清单不应包含：

- `src/` 或 `frontend/` 代码；
- 数据库迁移；
- Docker Runtime/Sandbox 实现；
- 测试或运行期数据；
- 新版本或 `v0.0.6` 标签；
- 服务器部署文件。

## 3. 通过与不通过

满足以下条件即可确认“阶段 0 通过”：

- 问题与根因记录准确；
- ADR、Charter、评测、任务图彼此一致；
- 当前 PDF→CSV 用例和未知需求泛化都进入强制门；
- 权限、外发、正式交付和阶段确认边界符合预期；
- GitHub 分支和 Issue 已建立；
- 没有提前修改 Runtime 代码或开始阶段 1。

如果不同意某项，不需要看技术日志，只需指出文档名称和具体条目。例如：

> 评测规格 P0-05 的复合来源范围需要调整。

## 4. 您确认后会发生什么

只有您明确同意进入阶段 1，才会开始三路线可抛弃赛马。阶段 1 完成后会给您：

- 三条路线的同语料结果；
- 一票否决检查；
- 加权评分与运维成本；
- 推荐方案和仍未验证风险；
- 面向普通用户的结果摘要。

届时仍不会自动进入正式 Runtime 实现。
