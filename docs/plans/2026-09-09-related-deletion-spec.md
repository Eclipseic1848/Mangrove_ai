# #137 关联感知的任务与数据清理

状态：实施合同。基线 `a80ee57d662fc18fc28371315b6106b636d3edf2`；依赖 #136、#118、#116 已关闭。依据 #113、已确认 ADR-0039；沿用原工作台与回收站，不新增资产管理产品。

## 目标、允许输入、要求输出和边界

目标：用户清理任务时，知道哪些原件、结果和关联任务会受影响；独占资料一起清理，共享资料默认保留，明确确认才清理共享资料。失败可恢复，不能以任务记录消失冒充正文删除成功。

允许输入：当前 Owner 的任务身份、服务端权威预检令牌、明确的共享处理选择、幂等键。测试只允许临时数据库、合成文件与受控 Runtime；不读取或清理真实业务数据、历史备份、生产资源或其他任务资产。

要求输出：完整确认与状态查询旅程、关联清单、同锁二次校验、持久删除意图及恢复记录、真实正文清理与最小身份墓碑、准确的保留任务能力投影、永久回归、双轴审查及同提交 CI。使用已有 SQLite、FileLock、Runtime 取消与文件路径校验，不新增依赖、通用资产框架或 Provider。

## 用户旅程及旧入口

保留“移入回收站”和“恢复”作为明确的可恢复记录操作；此时正文尚未删除。真正的任务与资料清理放在永久删除确认中，不静默改变已有回收操作的后果。永久删除先预检，再给出实际清理对象与受影响任务；默认保留共享资料，危险选择必须显式开启。取消初始聚焦，清单未知或失效时不得执行。

原 30 天到期清记录路径不能绕过新确认：不凭既往“只删记录”操作推导物理清理授权，也不能先清掉判断关联需要的历史修订。旧后台调用需保留安全兼容入口，未有明确清理操作时不自动清理这些任务，界面不能继续承诺 30 天自动永久删除。

原永久删除 API 不得保留无确认旁路；没有计划/幂等身份时明确拒绝并引导新流程。已有单上传删除入口至少必须核全部保留关系及未闭合使用，共享对象拒绝旧直接删除并引导关联清理，不扩大为新的资料管理界面。

## 对象、引用与确认快照

从目标所有历史修订与正式输出登记枚举三类来源及自身生成的结果；按 Owner 和不可变 ID/hash 归一。引用复用 #136 的所有历史修订、运行、预览/导出 active/unknown、正式消费关系，不能仅检查当前修订或第一页。生产任务仍保留的正式结果也是保留关系：删除消费者 C 不得把生产任务 A 的结果 B误判为独占。正式消费任务记录已清理仍保留真实正式消费关系。

目标自身的历史引用和本次一起清理的自产结果消费关系不形成虚假的“共享”；其他任务、独立正式结果或实际未闭合使用必须保留。计划绑定完整对象身份、全部引用快照和明确 keep_shared/delete_shared 选择；执行前同一规范源锁下重新核验。新增引用、对象版本或 Owner 权限变化使旧确认失效，不自动接受更大的清理范围。分页沿稳定快照，不完整查询不能显示零引用。

## 运行、并发与恢复

先持久记录删除中意图，阻止新冻结、正文读取及正在依赖这些来源的发布提交，然后释放短事务锁请求现有 Runtime 停止。不得持源锁等待需要该锁退出的 Worker。所有实际相关历史 Run、采集和在途发布均须核实停止；仅 UI 状态或取消请求回执不足以证明静止。

现有机制是取消及资源停止，不是任意时点的可恢复暂停。界面如实显示“停止依赖任务后清理”，不承诺原 session 原地续跑，不停用整个 Owner 代替任务级停止。其他任务记录及其独立正式结果保留；删除来源后标记不能按原来源完整重跑/复验。历史 QA 事实与当前可复验性分别表达。

再次取得规范源锁、核实引用与 active/unknown 使用后逐项清理。未闭合响应、取消失败、Worker 不明、路径/hash 变化、磁盘清理失败均保持未完成。持久操作绑定 Owner、幂等键、原计划与已完成对象；同键异请求拒绝，超时后查询原操作，恢复沿原操作而不暗换键。重启后验证已完成项及剩余项；不得用 TTL 把未知读取视为结束。

停止后复核以用户确认的对象与引用身份集合为上界：本操作已证明的 Run 停止、读取完成、已清理项只可收缩，不因自身状态变化使操作永远失效；新增任务、正式消费关系或对象身份仍须重新确认，不能仅比较总数或忽略变化。若已有删除意图且清单失效，原操作进入需重新确认状态，保留已完成事实，允许在同操作下提交新的权威确认；不暗换幂等键、回滚已删除正文或留下无法恢复的永久锁死。

## 正文清理与最小保留

清理范围必须按实际读写调用者核对：原上传及元数据、网页正文/预览、被清理输出本体、源观察报告、相关 Runtime staging/session/临时资料包及复制正文的中间记录。只清理经 Owner、冻结 Run/对象及合法根路径核实的对象；Windows 递归操作前确认绝对路径在精确目标内。不要清整个 Owner 根或误删其他任务独立发布目录。

正式 B 是独立保留结果时，不因原件 A 删除而被连带清理。保留任务的用户需求与正式结果也不能作为“缓存”误删；实际正文副本与独立产品结果的分界必须有代码路径和回归证据。

最终只保留必要删除事实和身份/hash映射，不留可导出的正文、旧缓存或备份旁路。网页必须保留 Owner/snapshot/artifact/hash 最小映射，以延续 #136 正式消费关系；不保留原网页全文、预览或业务查询文本冒充墓碑。现有不可变表触发器的受控删除变更必须通过新增显式迁移完成，禁止运行时关闭触发器或改旧迁移摘要。物理清理完成后才标记完成并清任务记录，操作状态在任务不存在后仍可查询。

## API 接缝

复用工作台鉴权及任务 API：只读任务删除预检、带预检令牌/共享选择/Idempotency-Key 的删除操作创建、Owner 操作状态查询与原操作继续执行。前后端实施前由后端给出具体 DTO、路由和错误语义，前端只接该权威合同，不自行计算删除范围或把 404 当成功。

确定拒绝与结果未知必须可区分；失效确认重取清单且恢复安全默认。执行成功才刷新实际受影响任务/来源/存储；Owner 切换和迟到回执保持隔离。采用现有 Radix 确认组件和引用展示，窄屏、键盘、屏幕阅读器状态完整。

## 验收

- 独占清理、共享保留、显式共享清理；纯上传/网页/派生结果、历史修订和正式消费记录均有真实隔离 API 与文件证据。
- A 生成 B、C 消费 B：删除 C 保留 A/B；删除 A 的共享原件保留其他任务及独立 B；不能经缓存、旧响应、恢复或重抓读取已删 A。
- Owner 拒绝、预检后新增引用、并发冻结/发布、在途读取、历史 Run、停止失败及未知响应逐项验证；危险动作之前明确拒绝。
- 逐项物理清理故障、幂等冲突、超时查询、重启原操作恢复；未完成不假成功，路径替换不删错对象，最小身份映射仍能解释保留的正式引用。
- 旧回收/恢复、永久删除、到期清理与上传删除入口不绕过确认；保留用户业务内容和独立结果的回归断言不削弱。
- 前端完整确认/安全焦点/取消零写/失效确认/未知恢复/Owner与任务切换，390与1440明暗、键盘及可访问性；Astra high 实施与验收。

真实业务数据、备份和生产物理清理仍需单独确认。本规格只授权隔离工程实现与验证，不能用测试通过替代真实运行或生产资格。
