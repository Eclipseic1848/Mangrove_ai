# Phase 4B 批次 7：正式数据工作台实施方案

> 日期：2026-07-27
> 状态：代码及内部回归已完成，用户验收未通过
> 基线：`v0.0.6` / `396586d`
> 边界：不改变批次 6 的 Delivery、Manifest、QA、owner 下载和幂等契约

## 1. 目标

把现有 `/data-prep` 升级为统一的数据工作台，将 Phase 4B 的自然语言计划、来源绑定、
有界执行、验证修复和正式交付变成普通用户可理解、可恢复、可追溯的 PC 端产品体验。

批次 7 不是单纯换皮。现有 `POST /api/semantic-harness/runs` 会等待 Harness 完整结束才返回，
无法满足刷新续跑、真实流式事件和随时取消，因此本批先增加一个薄工作台编排层，再整合正式前端。

## 2. 已确认的产品约束

1. 沿用 Mangrove 现有浅色/深色主题和总体视觉语言，不新建独立顶级产品。
2. 清晰、低风险任务自动执行；只有实质歧义、外部数据外发或改变输出语义时暂停。
3. 执行过程只显示简洁、事实型真实事件，不展示思维链，不使用逐字假流式和 Emoji。
4. 文件预览完整保留：结果在中间，来源与原文件预览在右侧，可折叠、固定和调整宽度。
5. 任务切页或刷新后继续；用户可取消排队或运行中的任务。
6. 结果优先展示预览、质量和下载；过程、证据、修复和 STP 放在可展开详情。
7. 结果修订创建不可变新 revision，旧结果、Manifest、QA 和下载继续保留。
8. 当前只实现普通用户自己的任务与回收站；管理员跨用户治理登记为后续项。
9. 当前只考虑 PC；当前可执行示例仅覆盖表格和文档，不展示多媒体能力。
10. 旧 Phase 4A 代码在批次 7 验收通过前保留为回退，不提前删除。

## 3. 信息架构

```text
Mangrove 主导航
└─ 数据工作台（保留 /data-prep 路由）
   ├─ 左侧任务栏：新建、筛选、历史任务、回收站
   ├─ 中间主区：任务输入、执行时间线、结果预览、下载和修订
   └─ 右侧检查器：原文件预览、来源证据、QA、修复记录和高级 STP
```

- 现有“任务中心”实际管理定时任务，导航文案改为“自动化任务”。
- 空状态首屏使用居中的自然语言任务输入和文件入口。
- 任务启动后，输入框固定在主区底部，作为同一任务的新 revision 入口。
- 来源预览默认收起；选择文件或点击“查看来源”后展开并定位对应页、段落、表格行或单元格。

## 4. 后台工作台编排层

新增轻量工作台任务聚合，不复制 Compiler、Binder、Harness 或 Delivery：

1. `workspace_tasks`
   - owner、标题、状态、活动 revision、创建/更新时间；
   - `deleted_at`、`purge_after`、取消请求和存储统计；
   - 状态至少覆盖 queued/running/needs_input/cancelling/cancelled/failed/completed。
2. `workspace_task_revisions`
   - 原始要求、输出格式、plan/binding/run/delivery 引用；
   - 不可变 revision；旧 revision 不覆盖。
3. 后台执行
   - 创建接口立即返回 `202`；
   - 复用 LangGraph checkpoint；
   - 本机默认轻任务并发 2、重解析/转换并发 1，其余持久化排队；
   - 服务重启时扫描 queued/running 状态并从 checkpoint 恢复。
4. 事件流
   - 事件写入 SQLite 后再推送；
   - SSE 支持事件 ID、断线重放、心跳和 owner 校验；
   - 前端只消费受控摘要，不消费模型原始思维。
5. 取消
   - 排队任务立即取消；
   - 运行任务设置取消标记，在节点和外部子进程安全点停止；
   - 清理 staging，保留审计，不发布 Delivery。
6. 预览与交付
   - 结构化结果使用服务端搜索、排序、分页；
   - 文档结果提供节点/段落预览和 EvidenceRef；
   - 下载继续使用批次 6 的不透明 `output_id`；
   - “下载全部”包含 outputs、Manifest、QA 和 trace，原件默认不包含。
7. 删除
   - 普通删除只进入本人回收站；
   - 30 天后才允许自动清理；
   - 恢复和永久删除都校验 owner，永久删除需要强确认。

## 5. 前端组件取舍

继续复用项目已有：

- React、Vite、TypeScript、Tailwind；
- TanStack Query；
- `react-dropzone`；
- `react-resizable-panels`；
- `react-pdf`；
- `sonner`、`lucide-react`。

新增成熟组件：

- `@tanstack/react-table`：无样式的大结果表格模型；
- `@tanstack/react-virtual`：行/段落虚拟化；
- `@microsoft/fetch-event-source`：带鉴权、AbortController 和重连控制的 SSE；
- Radix Dialog/AlertDialog/Tooltip：歧义、外发和破坏性操作确认；
- `@dnd-kit/core`、`@dnd-kit/sortable`：文件卡片排序；
- `@axe-core/playwright`：关键页面无障碍门禁。

不引入第二套完整上传 UI。上传继续使用 `react-dropzone`，只为现有上传 API 增加可观察进度和重试，
避免 Uppy/Axios 与当前 fetch/API 封装重复。

## 6. 普通用户流程

### 6.1 首屏

- 自然语言输入；
- 拖放、点击、粘贴文件；
- 文件卡片、上传/解析进度、失败重试、移除和排序；
- 自然语言输出要求与可编辑格式标签；
- 6 个当前可执行示例；
- 内嵌三步引导，首次成功后自动折叠，可从帮助入口重新打开。

默认格式：

- 表格：XLSX；
- 正式文档：DOCX + PDF；
- 演示文稿：PPTX + PDF；
- 结构化数据：JSON；
- Manifest、哈希、QA 和 trace 始终内部保留。

### 6.2 执行

时间线只显示类似以下事实事件：

- 正在读取 3 个文件；
- 已识别 12 张工作表；
- 正在按订单号去重；
- 正在生成 XLSX 和 JSON；
- 交付文件检查通过。

实质歧义一次只显示一个问题。外部 OpenAPI 必须说明目标服务、外发数据类型、目的和范围，
确认只对当前 task revision 生效。

### 6.3 结果

- 质量只显示“可交付 / 有警告 / 未通过”；
- 表格预览显示当前范围和全量行数，下载包含全量；
- 文档预览和结果预览不替代原文件预览；
- 每个下载卡片显示格式、文件名、大小和 QA；
- 支持下载全部；
- 点击字段、行、结论或段落的来源，在右侧原文件中定位；
- 底部自然语言修改创建 V2/V3，不覆盖旧结果。

## 7. 验收矩阵

### 7.1 后端

- 创建任务快速返回，后台继续；
- SSE 断开重连不丢事件、不重复展示；
- 明确任务不反复确认；
- 实质歧义只产生一个活动问题；
- 外部 OpenAPI 未确认调用次数为 0；
- 取消排队/运行任务均不发布正式 Delivery；
- 跨用户任务枚举、预览、事件、恢复、下载和回收站访问均为 0；
- 版本不可变，旧 Delivery 继续可验证；
- ZIP 默认不含原件，可选包含原件；
- 回收站恢复、永久删除和 30 天清理边界正确。

### 7.2 前端

- 1366×768、1440×900、1920×1080 可用；
- 浅色和深色主题无不可读状态；
- 首屏、执行、需确认、失败、取消、完成和回收站均有明确空/错/加载状态；
- 刷新后恢复任务和时间线；
- 表格全量搜索/排序由服务端执行，不只处理当前页；
- 原文件预览、结果预览和证据跳转均保留；
- 无逐字假流式、无思维链、无 Emoji；
- 键盘可完成上传、排序、确认、取消、下载和来源查看。

### 7.3 自动化门禁

- 后端定向测试；
- Phase 4B 批次 1–6 回归；
- 全仓 pytest；
- 前端生产构建；
- Playwright 真实旅程；
- axe 无严重/关键无障碍问题；
- 深浅主题和三种 PC 尺寸截图人工复核。
