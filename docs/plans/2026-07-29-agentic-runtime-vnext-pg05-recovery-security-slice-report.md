# Agentic Runtime vNext PG-05 恢复与安全纵切面报告

> 日期：2026-07-29
>
> 状态：恢复、幂等、所有权和提示注入取得阶段性证据；PG-05 整体未完成

## 1. 本轮目标

本轮只处理 Pi 管理员灰度的生产基础门，不切换默认入口、不创建正式 Delivery、不实施
服务器部署：

- 服务异常退出后恢复同一 Pi JSONL 会话；
- 用户取消必须显式到达任务容器硬终止接口；
- 重复创建请求不得启动第二个 Pi Run；
- 另一用户不得取消任务或下载候选；
- 来源中的恶意指令不得改变任务目标或扩大权限；
- 增加一项未参与前序适配的 TXT → JSON 真实任务。

## 2. 实际实现

### 2.1 使用 Pi 官方会话恢复

- 使用 Pi 0.80.10 官方 `--session <path>` 加载精确 JSONL 会话，没有自造会话格式；
- `runtime.preparing` 在容器启动前持久化 `run_id`、工作区和容器名；
- 服务启动恢复 `RUNNING/PREPARING` 任务时调用 `resume`，不再次调用 `start`；
- 恢复前重新校验工作区属于同一 `user_id + task_id + revision + run_id`；
- 重新计算只读来源哈希，来源缺失或改变时失败关闭；
- 先终止可能遗留的旧容器，防止两个 Agent 同时写同一候选目录；
- 找不到有效会话时保留旧 Run，创建新 Run 安全重放，不覆盖旧证据。

### 2.2 取消、所有权和幂等

- 工作台取消先显式调用 Runtime 硬终止，再取消 Python 编排协程；
- 容器索引由单一 `task_id` 改为 `user_id + task_id + revision`；
- API 所有权测试确认另一用户取消和候选下载均返回 404；
- 创建接口支持标准 `Idempotency-Key`；
- 同一用户、同一键、同一请求返回原任务，不再次启动 Runtime；
- 同一键更换目标或来源返回 409；
- 前端使用项目已有 `nanoid` 生成用户动作键；网络失败后相同表单重试沿用同一键，
  修改表单后生成新键，兼容 Mangrove 的局域网 HTTP 访问。

### 2.3 来源提示注入边界

- 使用 Pi 官方 `tool_result` Extension 给文本工具结果统一增加“不可信工具数据”边界；
- 明确禁止执行来源或工具结果中要求改变目标、扩大权限、读取其他用户目录或外发的指令；
- 保留原有 6KB 上下文截断和定向读取提示；
- 独立 Verifier 继续把候选与证据视为不可信数据，模型只给验证结论，没有发布权限。
