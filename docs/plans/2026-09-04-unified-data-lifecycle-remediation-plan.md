## 1. 结论与产品目标

整改不是仅修复一批 Bug，也不是另做聊天界面。目标是：让普通业务人员用自然语言，在一个
工作区内完成“理解需求 → 取得或选择数据 → 处理分析 → 检查结果 → 交付 → 再利用 → 删除”。
系统应主动承担工具和处理路线选择；用户决定业务含义、来源权限与重要范围，而不是负责拼装
技术工作流。纯文件、纯联网、混合任务是同一能力集合的组合，不是三套互不相通的产品模式。

当前已有较好的任务、证据、Owner、Runtime Adapter、独立验证和交付基础，但尚未形成完整的
统一产品闭环。此前 P1-01 和当时 GitHub Issues 关闭，不等于整个 P1 完成，也不等于功能覆盖或
生产安全合格。

### 已确认的用户与场景

- 首要用户：不懂编程的业务人员；专业人员仍可检查来源、规则、工具、版本和结构化结果。
- 纯文件：表格清洗、过滤、合并、计算、对比；文档/扫描件抽取、问答、总结、改写及格式交付。
- 纯联网：无需用户先提供网址的公开搜索；按任务要求取得数据、处理分析、保留原始来源。
- 混合：文件与网页、多个文件、旧来源与新来源、历史结果与新文件共同处理。
- 持续使用：多轮补充或纠正要求、选择旧数据继续加工、模板/个人记忆复用、自动任务与反馈。
- 这些场景是验收覆盖集合，不是 Query 分类器的穷举标签，也不承诺支持所有网站和文件编码。

### 不可扩大的范围

- 外部系统永久只读：无数据库写回、系统同步、业务结果投递/发布、社交写操作；不是确认后开放。
- 本轮不实现音视频，也不提供外部程序读取接口；两者列入后期路线。
- 不新建并行 Agent Loop、第二套任务真相、另一套插件市场或复杂预算/计费系统。
- 不迁移未上线旧任务和旧报告；也不借此删除真实数据、备份、Secret 或其他任务改动。
- 不把界面做成新的通用仪表盘；保留品牌基调，但用户明确否定现有样式，允许重做布局、字体、
  密度及交互。最多两种字体，不建立第二套设计系统。

## 3. 目标用户流程

```text
用户自然语言＋可选文件/网址/已有数据
    → 理解目标；必要时读取少量数据并问一个关键问题
    → 在获准范围内取得/选择来源，展示可重开的内容与缺口
    → 冻结目标、来源及所选模型，执行工具或隔离脚本
    → 独立检查内容、证据、数量、格式与完整性
    → 展示回答、可预览结果与按需下载
    → 继续加工 / 引用到后续任务 / 刷新为新来源 / 关联感知删除
```

### 交互准则

- 一个自然语言输入区。文件、网址和已有数据是附件/来源，不让用户先选技术模式或 Runtime。
- 需求充分且权限明确时直接推进，不强制填写“数量/完整性/输出格式”技术表单；系统提出合理
  默认，影响业务含义或范围时才问。不能用关键词分类穷举 Query 或按固定任务模板强行执行。
- “帮我看看这些数据”先检查结构和样例、提供具体发现与建议；不直接编造分析目标，也不循环
  追问一长串问题。少量说明或澄清不必每次生成文件，正式数据结论仍必须有相称验证与来源。
- 原始表达、当前理解与执行草案分开；用户改目标形成新修订，旧结果保持不变；安全点切换与
  立即停止沿用已有规则。默认继续处理现有数据，刷新来源必须明确，不能把重试变成重新采集。
- 目标要 10 条而只取得 9 条：展示已有 9 条及本次缺口，不留空白，也不把它说成“全网只有 9 条”。
  原硬性目标未达标时不能冒充正式完成；用户接受缺口则形成新修订，复用已有来源不强制重抓。
- 超时、登录未知、确实无匹配、获取失败与解析失败分别解释；重试要保留历史事实。模型结果
  未知时按已有规则暂停，不静默切模型或无限重试。

### 工作记录与界面

保留红树林青、品牌标识、明暗主题和有效预览能力；不再保留当前不可接受的布局和交互。
推荐“任务案头”：一个任务导航、连续自然语言对话、统一输入、按需来源/结果画布；专注报告是
同一任务视图，不是第二种模式。详细方向、现状渲染证据和跨页旅程见
[前端重设计蓝图](2026-09-04-unified-workspace-ux-blueprint.md)，行为草案见根目录 UX-CONTRACT.md。

执行时默认折叠行展示当前动作、耗时与行动数；展开实际工具名称、用途、安全判断摘要、产出、
失败与恢复，不展示原始思维链。扫码、范围确认等待办在折叠区外可见。支持键盘、焦点、窄屏和
reduced-motion。UX01 先交可交互原型并获得视觉反馈，不能把本轮规划当成新界面已经验收。

来源获取前的会话与执行 WorkSession 分开计时但连续呈现；WorkSession 仍绑定 Run。每次真实
模型调用都记录 Provider 用量和未知值，不能漏掉澄清/规划费用，也不能在会话与 Run 汇总时
重复记账。参考费用仅在匹配的官方价格可得时显示，不建设账单或复杂预算系统。

## 4. 数据保留、复用和删除

### 4.1 保存什么

1. 原件层：用户上传原件、实际读取的网页/接口内容；来源网址、最终网址、获取时间、内容身份。
2. 可处理表示：完整解析正文与记录、必要的结构信息、解析缺口；Markdown 便于人读，JSON/JSONL
   便于程序读，CSV/XLSX 用于适合行列的数据。统一 UTF-8、明确字段类型/空值和版本。
3. 结果层：独立生成的候选、验证结论与正式结果，保留到原件及来源记录的对应关系。

有意义的正文链接保留，但未经获取的链接/图片/附件不得声称已离线保存。未请求的站点资源不
自动镜像；Cookie、Token、密码、二维码及工具秘密日志不进入导出。读取网页内容时禁止执行
其脚本。不存在可靠原文解析时保留原件并说明缺口，不用模型摘要冒充原文。

不先建设通用数据湖或独立资产管理产品：复用 SourceSnapshot/Artifact/Delivery 的不可变身份，
增加必要的引用关系、选择入口和导出投影。大文件分块处理，导出按需生成；不能把全部数据塞进
模型上下文。缓存以 Owner/内容身份/规则版本区分，缓存命中不能绕过当前访问或删除状态。

### 4.2 引用与删除

后续任务可使用旧来源或正式结果而不重复上传/联网；派生结果再利用须保留“它是加工结果”的
语义，不能自动升级为外部原始事实。检索只在 Owner 有权使用的数据内，不默认跨用户分享。

删除前由服务端计算保留任务全部修订的引用，不仅查询当前页面或运行中任务：

| 情况 | 用户选择与行为 |
|---|---|
| 无其他任务引用 | 删除任务时一并处理其独占来源和结果 |
| 有其他引用，选择保留共享数据 | 删除当前任务及独占数据，保留其他任务仍引用的内容 |
| 有其他引用，明确确认删除共享数据 | 先暂停依赖执行，删除确认的数据，其他任务和独立结果保留并标明来源已删除 |
| 暂停或物理清理失败 | 显示未完成及可重试状态，不声称数据已清除 |

实施规格必须包含确认对象清单、执行时引用二次核验、防止新引用与删除竞争、幂等恢复及最小
审计事实。不能破坏不可变历史身份后仍声称结果可重验。备份的实际处置与保留政策单独处理；
本轮规划不承诺抹除全部历史备份，更不执行真实删除。

## 5. 技术路线：继承而不是重建

| 现有 Module / Interface | 本轮职责 | 不允许变成 |
|---|---|---|
| 统一前端＋ConversationSteering | Query、澄清、附件/旧数据、修订及进度投影 | 第二套聊天执行系统 |
| SourceAcquisition＋现有 Connector/Collector | 搜索、获准读取、解析、来源封存与登录暂停 | 绕过 Owner/Vault 的自由爬虫 |
| SemanticTaskLifecycle | 同一任务创建、暂停、恢复、取消、重试、验证与交付协调 | 承担全部业务的大型调度器 |
| AgentKernel＋CoreMind Adapter | 推理、工具循环、Context、Checkpoint、控制与事件 | Mangrove 自造的第二个 Agent Loop |
| Pi/coding-agent＋CapabilityHost | 已验证的隔离脚本和工具执行 | 向模型直接暴露宿主文件或 Docker Socket |
| CapabilityCatalog/Governance | 已安装精确版本复用、缺失能力发现、确认后装载 | 每次重新联网找工具、一次成功自动全平台安装 |
| CandidateVerification＋DeliveryPublishing | 独立检查与唯一正式交付 | Agent 自评成功即可发布 |
| ModelConnection/Broker/Vault | 用户所选模型、Owner 授权与原生用量 | 静默回退模型或共享 Cookie |
| 模板/记忆/调度/反馈 | 复用同一目标、来源和生命周期 | 注入隐藏指令、另造报告链 |

CoreMind 0.7.1 是现有锁定证据，不等于本轮已评估上游最新候选。保留已验证 Pi/Harness 能力，
只从 Adapter 或共享 Module 接入。上游升级先固定提交、协议、制品 digest，再验证控制、事件、
用量、工具和恢复；既有 Run 不变更内核，不操作由其他任务持有的 CoreMind checkout。

优先评估已部署/已安装搜索、抓取、解析能力；Agent-Reach 只提供渠道知识与体检线索。候选
工具/MCP/Skill 必须检查许可证、精确版本、真实只读能力、Owner 凭证隔离、输出和清理边界。
真正缺少工具时再提请安装，不整包替换、不运行浮动 latest、不以宿主全局安装作为快捷路线。

前置澄清/搜索的请求身份、授权及用量要在 R1 规格中落实：可记录交互与来源获取事实，但不能
伪造已冻结 TaskRevision 或正式执行 Run 来套用旧接口。若 Adapter 不支持所需控制，先以隔离
原型证明最小接口调整，不借机建立旁路内核。

## 6. 实施顺序与阶段产物

以下 R0～R6 是整改工作包标识，不是新版本号或新的独立平台。所有阶段按完整用户纵切片交付，
不是先写完后端再整体补前端。技术实现方案尚须按每片进入规格与测试，不在本规划中假定已验证。

| 阶段 | 用户可见结果 / 产物 | 依赖与退出门 |
|---|---|---|
| F0 前端先行设计 | 统一旅程、能力保留矩阵、宽窄屏/明暗交互原型、组件归属与跨页行为 | 与 R0 独立准备；用户看到并操作原型后确认视觉方向，再进入对应实现，不以文档替代 |
| R0 基础修复 | 修复 D01～D16；关闭匿名读取、错结果、错误配置、取消与登录撤销漏洞 | 每项红转绿回归；D01/D06/D07优先；多人开放前认证、审计、限流必须完成 |
| R1 文件任务统一闭环 | 一个输入区处理文件、模糊 Query、图片/扫描件、多轮修订；保留预览、多格式交付、工作记录 | 能力保留矩阵＋前置请求授权规格；文件完整链及失败/取消/版本 E2E |
| R2 自主公开联网 | 仅输入需求即可搜索、选源、读取、解释缺口并输出；原始网页可人读/机读导出 | 复用 R1 生命周期；搜索结果不能直接当已读取证据；跨站范围、SSRF、取消验证 |
| R3 混合与再利用 | 文件＋网页＋历史来源/结果在同任务处理；可自然语言继续加工；实现关联感知删除 | R1/R2 已稳定；去除来源 XOR，不复制执行链；混合证据/一致性/删除竞态全部通过 |
| R4 认证与受控连接来源 | 小红书 Owner 隔离扫码与恢复；已有 HTTP API/数据库只读能力接入统一体验 | R0 会话/Owner/撤权；R2/R3 来源接口；真实账号/新增工具/生产数据单独授权 |
| R5 共享能力完整继承 | 文件、联网、混合任务统一使用模板、记忆、自动任务、反馈和已安装工具 | 全部通过同一主链；普通用户能力资格合规；能力保留矩阵逐项验收后再退旧入口 |
| R6 集成与可用性验收 | 多人、故障恢复、资源配额、性能、键盘与无障碍、启动部署文档 | Critical/High 清零；全链真实代表任务、10–50人目标验证；形成用户验收候选，非自动发布 |

### 优先的小步工作项

- R0a：静态文件限制与安全引导（D01/D02）；独立可先交付，不等待统一架构。
- R0b：取消与清理（D06/D12）和结果身份（D07）；故障注入必须先于新来源扩展。
- R0c：过滤、分页、调度 Owner、前端收口、竞态、遥测和可访问性（D09～D16 其余项）。
- R0d：平台会话、停用任务、限流及受审计正文访问（D03/D04/D05/D08），沿 ADR-0037 实施。
- F0/UX01：先解决双工作区的统一旅程和视觉方向；UX02 的输入/导航、UX03 的流式记录、UX04
  的来源/结果画布分别为前端主线，UX05 收拢辅助页面，不能把前端全推迟到 R6 美化。
- R1a：先列出现有用户能力及测试，建立“不能丢”的保留矩阵；并冻结前置澄清的 Owner/用量契约。
- R1b：一组文件从自然语言到可验证交付；R1c：图片/扫描件与模糊目标；R1d：多轮修订与折叠轨迹。
- R2a：无 URL 的公开搜索→正文获取→结果；R2b：原始网页导出与缺口呈现，覆盖获取失败。
- R3a：多个来源共同冻结和执行；R3b：旧来源/结果复用；R3c：引用关系与删除的失败恢复。
- R4a：小红书“有效/失效/未知”三态及扫码；R4b：同 Owner 多任务恢复、跨 Owner 拒绝；
  R4c：已有 HTTP/数据库只读连接接入。后两者不等于对外提供 API，也不允许写回数据库。
- R5a：模板/记忆应用到所有来源；R5b：调度和反馈进入同一主链；R5c：已安装工具复用与安全发现。
- R6：完成整体验收，在对应能力验收后停止旧入口的新任务接收，仅清理已证明失效且不含用户
  数据的代码/文档。

R0 的独立修复可在互不重叠文件中并行；不得因此复制 checkout/worktree。没有形成 R0d 证据前，
R1～R5 只能在受控开发/验收环境验证，不能对非可信用户开放。每片的普通工程实现、测试与审查
以证据放行；这份计划本身不发起提交、PR、安装、迁移或真实站点调用。

## 7. 功能保留矩阵与验收样例

实施 R1a 必须定位现有入口、共享 Module、测试证据与目标入口；现有代码存在不等于功能已验收。

| 必须保留/补齐 | 核心验收 |
|---|---|
| 上传、来源选择、来源预览 | 原件可重开；文件格式与受支持能力准确；超限、损坏、密码保护文件明确处理 |
| 多文件与表格操作 | 多 sheet、重复列名、编码/日期/空值、重复游标、合并冲突；不能默默丢行 |
| 文档、图片、扫描件 | 分页/表格/图片位置能追溯；OCR 不确定与失败可见，不把识别结果装作原件 |
| 自然语言、多轮追问 | 改写、口语、缺条件和连续修订不要求固定词语；相同意图语义一致，实质改变产生新修订 |
| 搜索与获取 | 无网址也能启动受控检索；来源不存在/阻断/超时不假报全网无数据 |
| 混合任务 | 文件＋网页＋旧结果可对齐处理；连接键不明确时询问；每个结果可回溯实际来源 |
| 结果与格式 | 按需回答、表格、图表、报告和已有输出格式；预览/下载/版本/QA 对应同一内容 |
| 原始数据导出与再用 | 阅读版与机器版可对应原件，保留链接/时间；重复处理不重复采集，刷新产生新来源 |
| 模板与个人记忆 | 三类任务共享；草案可见、Owner 隔离、不覆盖当前指令、不成为凭空证据 |
| 自动任务 | 普通用户创建任务后按计划进入同一主链；本人模型/来源授权正确，过期或登录待办暂停 |
| 反馈 | 绑定任务/修订/结果，管理员默认无正文，审计查看有原因且可追溯 |
| 工作记录与用量 | 流式行动默认折叠；真实时间/Token/未知；断流重连不重跑，不暴露秘密/原始思维链 |
| 管理、配置和启动 | 角色一致、账号停用生效、连接配置可用、8088统一入口、start_all本机可验 |
| 删除与保留 | 独占一起删、关联先确认、共享删后其他结果保留、运行依赖先暂停、失败不假成功 |

至少形成以下黄金任务，各自配精确断言，不只看最终页面截图：

1. CSV/Excel 清洗计算与新文件交付；改变 Query 表达后得到同一业务结果。
2. PDF/Word/扫描件抽取或总结；既有文本和 OCR 的证据、遗漏与不确定明确区分。
3. 无网址公开调研；结果、原文、链接与机器可读明细齐备，不以搜索摘要代替正文。
4. 表格＋公开网页补充/对比；存在不同名、同名和缺失项，不能强行拼接或编造补全。
5. 用昨天的数据与新文件再分析；网络调用断言证明未重抓，显式刷新才访问外网。
6. 数量不足/来源失败的部分结果；已有结果可见，正式状态不冒充原目标完成。
7. 任务中修改要求、断线重连、取消、服务重启与发布恢复；无重复调用/交付或迟到资源。
8. 小红书登录过期扫码、网络异常状态未知、同 Owner 后续复用、跨 Owner 永不借用 Cookie。
9. 三类来源应用相同模板/记忆并进入自动任务；无旁路全局凭证或旧报告生成。
10. 删除任务的全部引用分支及并发删除/复用；重启后不复活已删除正文。

真实网络、真实账号和付费模型验证需要独立授权；其余先以本地固定样本、隔离数据库和故障桩
执行。样本与真实验收明确区分；不能用真实业务数据伪装 fixture。

## 8. 验证、依赖与发布门

### 每片完成门

1. 需求与禁止项对应到可观察验收；相关旧能力列入保留矩阵。
2. 按 TDD 建立失败证据，最小实现后检查调用者与兄弟路径，保留回归测试源码。
3. Module/Adapter 契约、API 与 Owner/角色拒绝和成功两侧验证；相关页面做浏览器完整旅程。
4. 故障、取消、并发、删除、网络/模型结果未知必须验证，不能只测成功返回。
5. Standards＋Spec 双轴审查；核心来源、授权、脚本、交付与删除增加专项安全检查。
6. 同提交 CI 及必要集成门通过后才进入常规 GitHub 工程收口；测试、用户验收和发布分开。

### 整体完成门

- R0 缺陷全部有修复与回归证据，Critical/High 为零；未覆盖能力如实列出，不把跳过算通过。
- R1～R5 功能矩阵逐项通过，三类任务共用一套任务、模型、事件与交付语义。
- 非可信正文/脚本/工具不可获得外部写能力；跨 Owner 数据、Cookie、密钥拒绝测试全通过。
- 原始数据、解析表示和最终结果身份可核对；来源未知、缺口、错误与已删除状态真实可见。
- 已有 ADR-0037 的 10–50 人目标、普通控制 P95 2 秒、首个持久化进度 2 秒及告警标准逐项验证；
  月可用性是需长期观测的目标，不能用一次压测证明 99.5% 已达成。
- 大文件/并发/配额、取消零残留、慢 Provider/Exporter、备份恢复方案和本机启动链完成相称验证。
- 代表用户完成真实任务验收，再形成私有多人使用候选；目标服务器、生产部署及真实发布仍独立。

新增依赖先说明用途、版本、复用理由、许可证/数据外发及风险，取得许可后安装。真实凭证、权限、
生产数据、不可逆清理、外部发布继续是人工门。不得强推、创建 worktree 或干扰 CoreMind 专属任务。

## 9. Roadmap 与版本计划

保留 P0 与 P1-01 的历史事实。R0～R6 是把后续 P1 按用户闭环重新排序：R1/R3/R5主要落实原
P1-02，R0d/R6落实P1-03，工具复用与受众落实P1-04，交互与性能落实P1-05；R2/R4补全来源纵切片。
来源和安全工作不得因原编号排序被推迟到最后。

| 里程碑 | 范围 | 不能声称 |
|---|---|---|
| 安全与正确性基线 | R0 | 完成全部产品能力或已有生产资格 |
| 统一数据核心候选 | R1～R3；R0通过 | 所有登录平台均可用、所有旧能力均已继承 |
| P1 功能完整候选 | 加上 R4/R5 | 已通过真实多人负载或用户验收 |
| P1 私有多人验收候选 | 加上 R6 与用户确认 | 已外部发布、已部署目标服务器或已有生产 SLA |
| 后期 P2 | 音视频、外部程序只读接口；有真实需求时再考虑目标服务器、多节点、对象存储等 | 外部写回/同步/业务结果投递会重新进入范围 |

不在本轮虚构 semver、Tag、Release 或排期承诺。具体版本号在真实验收及发布计划冻结时决定；
工程工期按首片基线、现有工具适配原型和上游证据估算，不以 Issue 数量猜测工期。
