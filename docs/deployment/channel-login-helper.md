# 多渠道本机登录助手

一个 Chrome 扩展维护现有10项采集账号：小红书、微博、抖音、B站、知乎、快手、贴吧、京东、
淘宝/天猫和拼多多。淘宝/天猫共用原配置项，助手不据此认定两个站点的登录状态相同。

助手帮助读取当前 Chrome 中适用业务域的 Cookie，明确复制后手动导入 Mangrove。
密码只在平台官网输入；助手不接收密码，不绕过验证码，不自动上传、保存配置、验证或恢复任务。

## 入口和安装

- 个人：设置 → 我的采集账号 → 对应渠道的“登录助手”，最终只进入本人该渠道配置。
- 平台：超级管理员从平台共享账号打开助手；原有管理员平台配置权限不变。
- 点击下载安装包，解压 `mangrove-channel-cookie-helper.zip`。
- Chrome 打开 `chrome://extensions/`，开启开发者模式，选择“加载已解压的扩展程序”，选中解压后的工具目录。
- 在扩展菜单中固定“Mangrove 登录助手”。旧小红书专用工具和下载地址继续保留；使用统一助手时，
  确认打开的是统一工具，避免混淆两个窗口。

网页的三步弹窗保持“官网登录 → 本机读取 → 确认导入”。网页不会检测扩展连接，也不会自动将
所选渠道传给扩展；请在扩展窗口核对并选择相同渠道。

## 每次使用

1. 在同一个普通 Chrome 个人资料中打开该渠道官网，核对账号，正常登录并完成平台要求的验证。
2. 打开扩展，选择相同渠道，确认业务域和本次读取说明。平台共享配置使用获准维护的平台账号。
3. 勾选本次读取授权，主动点击读取。首次使用该渠道时，Chrome 会请求其必要站点权限；拒绝后不读取。
4. 检查结果，显式复制，再回到 Mangrove 的原配置框手动粘贴，按原流程验证并保存。
5. 关闭扩展窗口会丢弃工具内存中的 Cookie；切换渠道也清除读取、同意和复制状态。
   已复制内容仍由系统剪贴板管理，完成后自行清理。

Chrome 可能保留曾授予的站点权限，可在扩展设置中管理；它与本次读取勾选是两件事。
即使已授站点权限，助手仍要求明确同意，并只处理当前所选渠道。扩展不申请全站权限，
不读其他网站、隐身窗口、密码、localStorage 或账号列表，不在后台运行。

## 渠道差异

| 渠道 | 注意事项 |
| --- | --- |
| 微博 | 采集使用 `m.weibo.cn`，只在其他微博域登录不一定产生可用的业务域 Cookie。 |
| 抖音、B站 | 采集还受浏览器环境及请求签名影响；复制成功不证明搜索、详情或评论可用。 |
| 知乎 | 当前签名依赖 `d_c0`；缺字段表示读取范围不足，不能直接判断账号过期。 |
| 快手 | 使用 `www.kuaishou.com` 的业务登录态；不能以公开资料可访问代替账号身份验证。 |
| 贴吧 | 当前身份探测缺少稳定账号 ID，不能据此证明同账号续跑。 |
| 京东 | 由原账号接口验证身份，不臆加一组字段作为完整登录成功条件。 |
| 淘宝/天猫 | 淘宝身份接口使用 `_m_h5_tk`；缺少时需在官网完成业务访问后重新读取。助手不混合不同站点同名 Cookie，淘宝身份通过也不证明天猫已验证。 |
| 拼多多 | 当前页面探测不能可靠证明身份成功，保持“尚未确认”，不把页面200判成登录有效。 |

小红书保留原会话与签名字段检查。各渠道的 Cookie 字符、域和路径规则分别适配现有采集器；
遇到分区、过期、同名不同值或当前采集器无法表达的内容时，工具给出明确提示，不静默改写或丢弃。

“已读取”只表示本机取得可导出的 Cookie，不表示身份、业务权限或永久有效。服务器执行验证和
采集时仍可能受到来源对网络、设备或行为的限制；访问受限或尚未确认不等于 Cookie 失效。
旧未知任务不会因修改 Cookie 自动重发。

## 分发和验证边界

统一源码包由登录鉴权的 `GET /api/config/cookie-helper/download` 分发，固定18件源码和原有图片，
无账号配置、Secret 或运行数据。旧 `GET /api/config/cookie-helper/xhs/download` 仍分发原小红书包。
下载工具代码不授予平台账号写权限，实际导入仍走原 Owner 和角色校验。

工程回归使用临时浏览器个人资料及合成 Cookie。代码、生产更新和真实使用结果分别记录在
[#295](https://github.com/Eclipseic1848/Mangrove_ai/issues/295)，不把工程通过替代本人官网登录或真实采集验收。
