# 小红书本机登录助手

现有渠道可使用[统一多渠道助手](channel-login-helper.md)。本页保留小红书专用工具的安装和兼容说明，
其原下载地址继续可用；设置中的统一入口使用新包，勿混淆两个扩展窗口。

助手帮助你在自己的 Chrome 中读取最新登录态，再手动导入 Mangrove。密码只在小红书官网输入；
助手不接收密码，也不自动上传 Cookie、保存配置或恢复任务。首版仅支持小红书。

## 入口和作用范围

- 在设置的个人采集账号中打开小红书“登录助手”，用于当前用户自己的配置。
- 超级管理员可从平台共享小红书账号打开同一助手，随后手动进入平台配置。
- 新平台助手入口仅超管可见；既有管理员的平台配置权限保持。下载工具代码不授予平台配置写权限。

网页不会检测扩展是否已安装，也不能直接读取其他网站的 Cookie。实际读取和复制发生在本机扩展窗口；
当前 HTTP 部署采用手动导入，没有网页与扩展之间的自动同步。

## 首次安装

1. 在登录助手中主动点击下载安装包，并解压 `mangrove-xhs-cookie-helper.zip`。
2. 在 Chrome 地址栏打开 `chrome://extensions/`，启用“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的 `mangrove-xhs-cookie-helper` 文件夹。
4. 在 Chrome 的扩展程序菜单中固定“Mangrove 小红书登录助手”，以后从这里打开。

扩展只申请 Cookie 权限及 `*://xiaohongshu.com/*`、`*://www.xiaohongshu.com/*` 两个精确主机权限，
用于读取根域和 www 的 Secure/非 Secure 登录字段；不包含通配子域或其他网站，不在无痕模式运行。
实际读取地址和官方登录链接均固定为 HTTPS www，扩展内容安全策略禁止联网。
无需安装 Python、桌面服务或其他依赖。

## 每次维护登录态

1. 使用安装助手的同一个 Chrome 个人资料，打开 <https://www.xiaohongshu.com/>，正常登录并完成官网验证。
   在官网核对账号：个人配置使用自己的账号；平台配置使用维护者获准管理的平台账号。
2. 打开扩展，进入“本机读取”，勾选账号和读取授权，再点击“读取最新登录态”。
3. 确认读取结果后，主动点击复制；助手只显示字段数量，不展示 Cookie 原文或推测账号身份。
4. 回到 Mangrove 的对应个人或平台编辑框，手动粘贴，按原流程验证并保存。助手不会替你提交。
5. 完成后清理剪贴板。关闭助手窗口即丢弃助手内存中的登录态；剪贴板由你手动管理。

读取成功只表示取得可表达的本机登录字段。基础身份、搜索访问与客户任务成功是不同结果；
Cookie 有值不代表账号有效，身份检查通过也不代表搜索已放行。旧未知任务不会因更新 Cookie 自动重发。

## 无法读取时

| 提示 | 处理 |
| --- | --- |
| 未找到或缺少会话/签名字段 | 回到同一 Chrome 个人资料中的官网完成登录并刷新，然后主动重新读取 |
| 无权读取 | 在 Chrome 扩展设置核对助手的小红书网站访问权限 |
| 过期、分区或同名冲突字段 | 在普通窗口直接访问官网确认账号并重新登录；助手不会合并不同来源的凭据 |
| 不支持的字符 | 当前采集器的字符串导入不能安全表达该登录态，请联系维护者；助手不会改写或静默丢弃字段 |
| 复制失败 | 检查浏览器剪贴板权限后主动重试；不会以明文展示 Cookie 作为替代 |
| 保存后仍提示平台验证 | 按官网正常流程完成验证；助手不能绕过平台验证或保证 Cookie 永久有效 |

## 实现与核验

源码位于 `tools/xhs-cookie-helper/`。登录后的安装包接口为
`GET /api/config/cookie-helper/xhs/download`，只打包固定七件工具源码和图片，不读取账号配置或运行数据。
包内文件缺失、超出单文件限额或是符号链接时拒绝下载，不返回不完整安装包。

扩展无后台、内容注入、网页消息桥、网络请求、遥测和凭据持久化；仅在用户主动读取时调用 Cookie API，
在主动复制时写入剪贴板。扩展内容安全策略禁止联网。回归使用临时浏览器个人资料及合成 Cookie，
不读取日常 Chrome 中的真实账号。工程、生产与真实使用结果分别记录在 [#293](https://github.com/Eclipseic1848/Mangrove_ai/issues/293)。
