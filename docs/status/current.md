## 2. 已实现能力

| 领域 | 当前能力 | 限制 |
| --- | --- | --- |
| 工作台 | 目标理解、来源冻结、版本、多轮追问、取消、历史和回收站 | 任务成功取决于来源、模型与输出要求 |
| 文件与交付 | 文件处理、初稿检查、用户接受或继续核对、正式交付 | 用户采纳与系统语义核验分开记录；正式交付检查文件完整性与质量 |
| 采集 | 来源约束、参数传递、隔离登录态、凭据恢复、图片/OCR 预算 | 各外部渠道需独立配置和验证；不承诺全站点可用 |
| 模型与复用 | 模型连接、个人记忆、模板、处理经验、自动化计划 | 通知与数据外发须获得相应授权 |
| 预览与交互 | Word/PPT 原版式预览、历史分页、局部错误恢复、键盘操作和角色引导 | 字体替换可能影响排版；真实读屏和手机软键盘未完整验收 |
| 运营审计 | 历史 Token 统计、筛选、CSV 导出、趋势悬停与五种时间粒度 | 未知用量保留未知；参考成本不是实际账单 |
| 能力治理 | Python Tool 与 Everything MCP 的验证、签名、发布、装载和治理链 | 平台受众限 `admin_gray`；普通用户市场与远程 MCP/Registry 未开放 |

任务抽象使用现有契约、能力注册、规划、执行和验证链路。旧 Harness 的 10 类 TaskFamily
中有 7 类在该入口接线、3 类拒绝；工作台使用 AgentKernel。新增类型需要贯通这些接缝，
仅增加枚举不能形成可执行能力。参见[能力矩阵](../agents/task-capability-matrix.md)。

## 4. 已知问题与未验证范围

1. 仍有间歇性 Provider 结果未知，尚未证明根因已消除；不得盲目重发可能已执行的操作。
2. 部分在线任务仍会选择不合适的来源，或无法满足体裁、时效及输出要求；冻结来源评测不能代替在线采集验证。
3. 自然语言约束提取存在覆盖盲点，包括部分调度前缀和多工作表要求。
4. 前端仍有较大分块警告；弱网加载、真实读屏、手机软键盘和多用户容量尚未完整验证。
5. 构建、离线评测和 React Router 存在待处理依赖告警，详见[安全策略](../../SECURITY.md)。
6. 目标 Linux 环境、公网访问、备份恢复、外部来源和代表业务须在实际部署后验收。
7. Pi 与 CoreMind 尚无同题同条件性能对照；候选验证结果不用于两者排名。
