# 私有多人实例运维候选

适用范围：ADR-0037 的10–50人私有实例。本文是待集成操作说明，不表示目标服务器已部署、长期可用性达标或告警接收人已配置。统一入口8088；5173只供开发。不要以开发热重载进程作为生产进程管理方案。

## 启动与失败关闭

使用已锁定的runtime/collectors依赖组及前端构建；CI的干净安装和构建结果必须绑定将部署的同一提交。测试依赖只用于dev/evaluation，不向生产镜像增加GPU依赖。

启动前执行 `python -X utf8 scripts/check_dev_database_migrations.py --webui-database <WebUI副本路径> --scheduler-database <Scheduler副本路径>`。此命令只检查；任一库落后则退出1。它输出的迁移命令是建议，不应自动执行。配置SecretRef/Vault/JWT缺失、版本漂移都须先解决，不能临时改为匿名或吞掉异常继续启动。

本机start_all.bat/stop_all.bat保持忽略和CRLF。端口被占用时先核项目路径、进程身份和祖先链；未知进程只报告，不按端口批量杀进程。公开dev_reload只管理自己创建的后端子进程，不能据此获得清理任意8088监听者的权限。

## 就绪、延迟与告警

`/api/health`仅说明HTTP进程应答；接单检查使用`/api/readiness`，覆盖数据库、worker及三个存储根的真实可写探针，200表示当前通过、503表示不可接单。不以模型返回速度替代平台就绪，也不把来源等待算作平台已完成。

目标环境监控应从应用进程之外采集，核心就绪连续失败300秒产生可追踪告警；恢复事件使用相同告警身份收口。普通控制P95超过2秒、持久首进度超过2秒和自然月99.5%预算分别记录；月统计需保留维护窗口及完整分母。指标标签仅使用状态/类别，不放Owner、任务、URL、正文或秘密。

现有OTLP为低敏轨迹输出，不等同于外部告警送达。目标监控端、接收人、通知费用与持续时间策略列入部署确认单；尚未配置或执行外部通知，不能把本地日志写成“管理员已收到告警”。运行日志目标30天、安全审计目标180天；实际轮转与容量需目标环境核验，不自动删除任务原件来满足日志保留期。

## 资源边界与压力

默认单上传文件500MiB、单任务处理输入500MiB、预览10MiB/20条记录；实际实例配置须启动时核验。候选在超额分块写盘前拒绝，磁盘不足返回507，提交失败只清理本次新对象，旧原件不变。正式原件仍遵循用户删除前保留及回收站协议；不得在配额到达时静默淘汰。

候选工作队列在内存最多256项，超出部分留在现有持久库、由维护循环接管；不是总任务数或总存储容量配额。待恢复任务按剩余槽位有界读取并排除本进程已排队/执行身份；取消态另以最多256项优先接管，后续轮次继续处理剩余积压。遥测另有256项有界队列和可见丢弃计数，不影响任务事实。

隔离列表负载P95 1.3753秒依赖临时WAL/FULL；生产未启用。50个真实登录Owner、聚合每秒5次到达、每Owner各一次创建和取消、合成阻塞Runtime的持续负载中，提交响应/持久首进度/取消P95分别为0.184/0.240/0.636秒，50项均实际停止。永久回归 `tests/test_ops_control_load.py` 默认复现此负载，并将完整指标写入JUnit；计时包含计划到达后的排队。它不证明真实模型质量、长期可用性或目标硬件性能。

50请求同刻突发仍未达2秒：原持久首进度P95 14.62秒，结构检查优化后5.08秒。`MANGROVE_LOAD_ARRIVAL_RATE=0` 可复验此压力上限；不得将持续负载通过写成突发通过。生产部署前需在目标磁盘/硬件与明确到达率下重测，不新增静默丢请求或放宽权限来制造通过。

结构检查仅缓存相同完整DDL、Schema版本、清单及必需列对应的纯结构缺口，最多8项；迁移版本和历史证据仍逐次现场读取，索引/列/约束/证据改变仍拒绝。决定使用WAL前核验目标磁盘及SQLite共享方式、备份路径和恢复演练；不能降低synchronous制造通过数据。在线备份可包含已提交WAL，但主文件SHA不覆盖WAL；使用 expected-source-sha256 时若存在非空WAL会失败关闭，须先停写并checkpoint后重新确认。

## 备份与恢复

先确定维护范围、文件允许列表和源SHA；WebUI/Scheduler及原件/密文边界需一致性备份，不能只备业务表。暂停写入或使用已经验证的一致性备份机制；WAL模式不能只复制主db文件。不要把Secret、密钥或恢复副本上传到工单或CI附件。

沿正式迁移机制的备份收据执行 `python -X utf8 -m src.database_migrations verify-restore --receipt <备份收据> --restored <隔离恢复副本>`；要求备份hash、integrity、FK及Schema检查全部通过。若需要迁移，先对副本运行status/plan，再经确认以`apply --expected-source-sha256`生成独立备份与收据。`apply`不是常规只读备份命令。

恢复演练只使用独立副本和隔离存储根，关闭外部执行/计划/模型请求；核验原件hash、Owner、冻结版本、待办和未知状态。未知Provider调用或取消清理未知不能重发或假称停止。副本验证通过也不授权覆盖原库、恢复真实任务、轮换密钥或删除旧备份。

当前能力与验收状态以[状态台账](../status/current.md)为准；生产配置、目标运行和真实告警仍未验收。
