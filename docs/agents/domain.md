# 领域文档使用约定

本仓库采用单上下文领域文档布局。

## 开始探索前

工程技能在分析或修改相关模块前，应按任务范围读取：

1. 根目录 `CONTEXT.md`（如果存在）；
2. `docs/adr/` 中与当前任务相关的 ADR；
3. 根目录 `handoff.md` 以及项目权威计划要求的相关文档。

文件不存在时继续执行，不把“先创建空文档”作为任务前置条件。`CONTEXT.md` 应在真正
确认领域术语、边界或关系时，由领域建模流程按需创建。

## 文件布局

```text
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   └── agents/
└── src/
```

当前不是 monorepo，不创建 `CONTEXT-MAP.md` 或各模块独立的 `CONTEXT.md`。如果未来演变为
多个清晰的业务上下文，应先形成架构决策，再切换为多上下文布局。

## 统一语言

- Issue 标题、方案、测试名称和代码中的领域概念应使用 `CONTEXT.md` 已定义的术语；
- 不应为同一概念随意创造同义词；
- 需要的概念尚未定义时，先判断是否确有领域缺口，再通过领域建模流程补充；
- 领域术语调整时，应同步检查相关 ADR、计划和交接文档。

## ADR 冲突

若方案或实现与现有 ADR 冲突，必须明确指出冲突的 ADR 编号和原因，不得静默覆盖。
需要改变既有决策时，应新增 ADR 记录替代关系，不回写历史决策。
