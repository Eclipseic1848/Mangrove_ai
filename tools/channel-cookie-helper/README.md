# Mangrove 多渠道登录助手

一个本机 Chrome 扩展，覆盖小红书、微博、抖音、B站、知乎、快手、贴吧、京东、淘宝/天猫和拼多多。密码只在官网输入，助手不接收密码、不代过验证码、不自动访问业务接口。

## 安装与使用

1. 从 Mangrove 对应渠道的“登录助手”下载安装包并解压。在 Chrome 的 `chrome://extensions` 打开开发者模式，选择“加载已解压的扩展程序”，选中含 `manifest.json` 的目录。不要加载收到的未知扩展。
2. 在同一 Chrome 普通个人资料中正常登录所需官网并确认账号。扩展内选择对应渠道，与 Mangrove 准备编辑的渠道保持一致。
3. 进入“本机读取”，核对实际业务请求地址，勾选本次同意后点击“授权并读取”。Chrome 仅申请当前渠道的固定业务站点及适用父域权限。拒绝授权不会读取；已授站点权限由 Chrome 管理，每次读取仍需明确同意。
4. 核对渠道和字段数量后主动复制，回 Mangrove 同渠道配置手动粘贴，再按原流程验证和保存。个人配置用于本人；平台共享账号由超级管理员维护。复制不会自动上传、保存、验证或恢复旧任务。
5. 完成后自行清理剪贴板。切换渠道或关闭窗口会丢弃助手内存中的本次结果；已触发的系统剪贴板复制无法由切换操作撤回。

## 范围与限制

- 只使用固定业务请求 URL 读取适用的 Cookie，包含与该路径匹配的字段。不把网页登录页、SSO 中转站或同平台所有子域的 Cookie 混成一份。
- 微博实际读取 `m.weibo.cn`；京东读取 `me-api.jd.com`；淘宝读取 `h5api.m.taobao.com`，不合并天猫域或宣称天猫已验证。
- 小红书仍要求 `a1/web_session`，知乎当前签名需要 `d_c0`，淘宝当前身份签名需要 `_m_h5_tk`。缺字段只提示范围不足；其他渠道没有明确的完整字段合同，不猜测必需字段。
- 过期、分区、域/路径错配、同名冲突及原采集器无法表达的值会拒绝导出，不改写或静默丢弃。快手和电商可保留值内等号，其他六社媒沿现有解析边界。
- 只显示渠道和字段数量，默认不展示正文，不推断账号昵称或身份。读取成功不证明身份、搜索、详情或评论权限有效；拼多多当前页面探测不能可靠验证身份，贴吧不能凭当前接口证明同账号续跑。
- 扩展没有后台、内容脚本、网页通信桥、网络连接、上传、遥测、localStorage 或 Cookie 持久化。权限申请与读取只由主动点击触发；切换后的旧请求结果不会更新新渠道界面。
- 渠道选择采用有标签的原生 select，接受 Chrome/操作系统拥有的弹出菜单与键盘行为。视觉、明暗主题和三步布局沿用既有小红书助手。
- 旧版小红书扩展与下载保持兼容；本包是独立统一助手，不会自动安装、更新或修改日常 Chrome 的其他资料。

本机扩展不识别 Mangrove 登录角色，也不授予平台配置写权限。实际 Owner 和权限校验由 Mangrove 原接口负责。
